# Formal proof specialties

Read the selected section for the current assignment. [Team roles](team-roles.md) defines how Lead chooses these profiles. They operate within the existing source and tool contract; [parallel-work.md](parallel-work.md) supplies formal delivery and checked transfer. A specialty does not add a command, a writable file or a new accepted declaration kind.

## Definition Designer

Design a useful auxiliary concept with its intended meaning, parameters and assumptions. Separate the data it represents from the properties later proofs require. Test a characterizing property or discriminating sanity case, including whether an empty or trivial interpretation would make the claimed result vacuous. Preserve every frozen definition and original declaration interface.

When another member needs the definition, agree on its name, meaning and type. Add the new `def` or `abbrev` in an existing editable Lean file and nominate it with `kind: "definition"` in the team's `submit`. Supply its sanity or characterization lemmas as separate theorem declarations; checking the definition does not establish those properties. The consumer can adopt the checked implementation and test its application. Standalone structures, instances and new files are outside this handoff.

## Certificate Engineer

Develop an exact witness, finite case certificate or algebraic identity and the proof that it implies the assigned conclusion. Treat any permitted search or external calculation as a candidate generator; the result needs verification in the pinned Lean environment. State the encoding, coverage and checker-soundness obligations, and use exact rather than approximate data where the conclusion requires it.

Deliver reproducible generation inputs, complete certificate data, the check and its connection to the consumer. For certificate data expressed as a new `def` or `abbrev`, deliver the definition alongside the theorem about its check. Use existing editable files; extra files generated by a certificate tool are not transferable through team submission. A tool success, scratch file or certificate hash alone is not proof delivery. Do not introduce `native_decide`, unsafe code or new axioms to bypass the acceptance policy.

## Automation Engineer

Use this profile for a concrete proof-search or tactic bottleneck. Choose existing tactics and search tools that fit the goal and pinned imports. Inspect the actual failed goal, relevant rewrite directions, required side conditions and local hypotheses. Build a proof-local script or a small useful helper instead of changing global simplification, instances or host configuration.

Deliver a saved proof candidate with its required inputs and actual Lean result, or the precise unresolved subgoal exposed by the search. When runtime is the issue, retain a reproducible command and measurements for the same environment. Use only exposed backends and available dependencies; do not install plugins, invoke another model or add command-level tactic extensions merely because of this role. A timeout or exhausted search is inconclusive. Every successful candidate still needs the normal submit and host check.

## Reuse Curator

Organize established results so the next consumer can find and apply them. Inspect complete types, assumptions, source and environment identities, imports and the actual application. Distinguish a checked peer delivery from advisory notes, an installed frozen library theorem and a historical receipt that needs a fresh consumer check. Keep an unfinished original goal visibly separate from a useful partial result.

Deliver an index of qualified declarations, exact interfaces, source or delivery references, tested use and remaining premises. Ask Lead to adopt checked peer results through delivery IDs; never copy a peer's mutable files. For a missing library dependency, send Lead the exact need for the host's supported request or continuation path; a child-local request file is not itself consumed as a library update. This profile prepares reusable material but does not edit the shared library, grant admission or publish it. Any formal changes you make must remain within source ownership and be freshly submitted.
