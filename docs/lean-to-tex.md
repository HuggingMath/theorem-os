# 从已验收的 Lean 证明生成 LaTeX 论文初稿

## 已实现的流程

从 TheoremOS 已通过独立验收的 Lean 证明出发，生成一份数学读者可以独立阅读、作者可以继续编辑的英文论文初稿。在 Web 工作台打开已完成运行的「论文初稿」，选择已验收的目标定理即可生成并下载包含 `template.tex` 和 `main.tex` 的 ZIP。下一步是在导出时编译 PDF。[TeX 到 PDF 的计划](tex-to-lean.md)

初稿按数学论证组织。短证明用标题、定理和证明即可。较长的证明可以用摘要、引理、章节和交叉引用来说明推导结构。相关工作、原创性和文献引用需要有作者提供或确认的依据。

## 模板和正文

| 文件 | 内容 | 更新方式 |
| --- | --- | --- |
| `template.tex` | 文档类、字体、版心、宏包，以及定理、引理和证明环境。通过 `\input{main}` 载入正文。 | 预先维护并记录模板版本。导出时附上生成当时使用的版本。 |
| `main.tex` | 标题、按需添加的摘要和章节、数学陈述与证明、公式和交叉引用。 | 写作、审阅和修订只处理这个文件。作者拿到源稿后可以直接编辑。 |

`template.tex` 是后续编译入口。`main.tex` 是文档体片段，可以使用模板提供的环境和标准 LaTeX 公式命令。文档类、宏包加载和外部文件引用由模板管理。同一个模板可用于多篇初稿，同一篇正文也可以搭配提供相同环境的其他模板。

## 写作与审阅流程

1. **准备输入。** 从已验收记录中取目标定理、最终 Lean 源码及验收结果。用户的原题或已确认的陈述可以帮助选用自然的术语。已有讲解可作为写作材料，缺失时直接从已验收的 Lean 证明开始。遇到关键库引理时，提供其声明和必要上下文。[现有证明讲解流程](informalization.md)
2. **写正文。** 写作会话直接产出 `main.tex`。保留定理的对象、量词、假设和结论。可以调整叙述顺序、合并辅助引理，或用读者熟悉的论证替代 tactic 展开的推导。公式符号和术语在全文保持一致。正文无需标注 Lean 行号或逐步对应关系。
3. **审阅。** 独立审阅会话先通读正文，再对照已验收的目标和必要的 Lean 上下文。检查陈述是否准确、改写后的推导是否完整、引理的使用条件是否满足，以及符号和交叉引用是否清楚。Lean 验收记录证明形式版本通过检查。论文审阅结论记录的是对这份正文的判断。
4. **修订和导出。** 写作会话根据具体意见修订 `main.tex`。导出前检查正文片段的结构、标签和引用，例如重复标签、未定义的内部引用以及误放在正文里的导言命令。仍有数学疑点的版本标为待审，并保留具体意见供作者继续编辑。实际排版和编译错误由后续的 PDF 编译检查。

## 接入现有仓库

Web 将论文初稿作为已验收运行下的独立任务，按目标定理和英文正文保存。每份初稿记录运行 ID、目标声明、Lean 源码的 SHA-256 和模板版本，方便确认改写所依据的版本。论文任务可以单独选择支持 Responses API 的服务商和模型。[Web 初稿任务](../apps/web/paperDrafts.ts)

生成弹窗优先使用这份初稿上次选择的服务商和模型，其次使用原运行兼容的配置。沿用原运行的服务商和模型时，服务端沿用该运行的推理强度。账号保存的 API Key、工作台提供的 API Key，或同一标签页为该地址记住的 API Key 都可以直接使用。需要调整时可展开「更改模型」，从工作台配置的 Responses API 服务商中选择。[工作台服务商配置](web-workbench.md#配置兼容-responses-api-的服务)

`src/math` 定义初稿结构、模板和正文检查，`src/solver` 执行写作、审阅和修订。Web 从独立验收记录选取证明材料，并负责页面入口、作业状态和下载。
