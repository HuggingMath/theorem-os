# 前端功能盘点与整理记录

审查日期：2026-11-02。对象：当前工作区的 `apps/web`，包含已完成但未提交的路线图与讲解入口调整。

## 本轮整理结果

第一批入口整理已实施，并接通了路线图节点与协作区：

- 简洁模式保留分区导航，以及有权限和状态条件的计划编辑、知识归档入口；长内容按需展开。
- 「原意与 Lean」成为明确入口。路线图任务节点可直接打开对应任务详情、声明对照；运行中的真实任务可打开定向指导草稿，仍需用户填写和发送。没有声明审阅记录时显示该任务的空态。
- 命令搜索新增原意对照、最终证明讲解、知识检索、归档记录与指导历史；搜索「形式化」定位到能力说明。已结束运行仍可查看指导历史。
- 新建研究明确区分原始 Lean 题目与研究要求；草稿提示保存于当前标签页。导入预览说明不恢复历史运行，并展示实际导入的 Token 上限、搜索策略、上下文策略及自定义规则数量。
- 使用说明补充 Lean 与自然语言、指导与知识、路线图和导入用途；同步中英文，保留舒展布局。

后续「接入」任务已实现自然语言 / TeX 原题的在线形式化：独立页面、持久任务、规划与编译、盲回译、双 Reviewer 审核、用户确认、带入研究草稿和冻结证据接续。部署需更新工作台与 worker 镜像，当前仅支持 Sub2API + deepseek-flash。以下盘点与问题描述保留为修改前的依据，已完成项以本节为准。

## 初始盘点结论

前端已经具备较完整的 Lean 研究、协作、审阅和验收能力。当前最突出的问题是默认简洁模式隐藏功能入口、相关内容分散，以及自然语言形式化尚未接入在线创建流程。

本次特别补查到：**在线协作里已有「声明与原意对照」，能同时查看原始数学意图、Lean 形式声明和独立回译。** 它位于「协作 → 详细 → 审阅」，并非只能在 CLI 报告里查看。上一轮只定位到最终证明讲解，遗漏了这条在线入口。

建议先恢复已有能力的可发现性，再接通自然语言输入的完整流程。简洁应减少首屏信息量，但保留通往每项主要功能的入口。布局继续保持舒展，路线图保留足够大的节点和具体引理内容。

## 整改顺序与验收条件

### 第一批：让已有功能能被找到

1. 简洁模式保留「任务、原意对照、审阅、指导记录、知识」等功能导航。内容可以折叠，入口不应整体隐藏。验收：新浏览器默认设置下无需猜“详细”的含义即可打开这些能力。
2. 「声明与原意对照」提供清晰命名和任务级跳转。验收：从某个引理可打开对应版本的数学意图、Lean 声明、回译和审阅结论；没有数据时不伪造翻译。
3. 命令面板和使用说明补齐「形式化、自然语言、讲解、知识、归档」搜索与定位。实测这些词目前均无匹配命令；“路线图”同时命中路线图与协作，应以用途说明差异。
4. 研究创建处明确“原始 Lean 题目”与“研究指令”，草稿说明保存范围，导入档案说明实际用途。验收：用户能在提交前确认研究对象和带入的预算配置。

### 第二批：贯通现有能力

1. 接入自然语言/TeX 形式化：创建 → 规划与编译 → 原题/Lean/回译审阅 → 批准冻结 → 开始证明。复用现有形式化服务和对照页，需要实际任务 API、状态和产物接续，不是加一个链接。
2. 路线图节点连接任务检查器、语义审阅、版本与回执、人工指导。保留计划依赖和实际证明使用关系的区别，不为视觉完整虚构边。
3. 知识库提供固定入口；运行中允许按当前任务过滤和引用，运行结束后仍能查看归档、指导和来源。
4. 若要面向不熟悉 Lean 的人分享结果，在已有分享预览中明确增加哪些已生成的讲解/路线图内容，再扩展快照。当前分享功能本身没有损坏。

### 页面组织建议

- 全局保持「新建研究、研究记录」，增加可发现的知识入口；模型、账号、外观放设置。
- 新建研究区分「已有 Lean 题目」与「自然语言 / TeX 题目」，后者在真正接通前明确能力状态。
- 运行页沿用现有「结果、路线图、协作、源码、活动」结构，减少迁移成本；让「协作」明确覆盖任务与审阅，并常驻功能导航。
- 路线图作为研究过程主视图；节点详情承担跳转，避免在同一首屏重复铺开流程图、依赖图和操作日志。
- 保留逐项高级证据，按需展开；保持空间和字号，不再通过缩小图或整块隐藏功能实现“简洁”。
