# 题目工作区与产品流程补全（三）· 2026-11-10

本轮在 `feat/product-continuity` 实现九项补充，叠加上一轮尚未提交的改动。保留现有品牌配色、数学排版与工作台结构。当前为本地实现和验证，尚未提交、合并或部署。

| 补充 | 入口与实际行为 |
| --- | --- |
| 统一题目工作区 | 我的研究卡片、运行菜单、定理项目和简报进入 `problem.html`。总览、证明路线、历次尝试、讨论与决议、用量与成果、阶段结论和简报沿用同一运行与任务上下文，地址保留精确版本和提交号，刷新及返回可恢复。 |
| 决议接到真实执行 | 议题决议可准备为指导或完整计划调整。提交前审阅目标、来源与版本；计划先预览，人工确认后执行。记录原议题、采用方案、决议、原目标与核对后的目标，分别显示投递、采纳和执行。 |
| 人工草稿恢复 | 候选、普通讨论、议题和回复保存在当前浏览器，按账号、项目和对应版本隔离。旧基准或旧修订保留原文，先核对再提交；不确定的提交结果保留草稿，延迟成功不删除后来编辑。 |
| 首次研究引导 | 首页按服务商、Key、连接检查和研究方式引导。展示人工确认题意与计划的实际流程、预算预设、当前额度与恢复时间。运行和只读示例保留阅读空间。 |
| 历次路线对照 | 题目工作区并排展示两次交互路线，标记任务新增、撤回与调整，以及依赖、推导、证明版本和检查证据的变化。陈述、形式化证据或环境不一致、环境身份不完整时分别展示，停止计算增量。 |
| 人工阶段结论 | 用户填写结论、适用边界、未解决问题和下一步，定稿冻结当时的原题、路线、任务版本与检查证据。研究变化后先核对，定稿后仍可交互阅读冻结路线。个人运行后来关联项目时保留既有结论。 |
| Library 在当前目标中试用 | 从任务带入精确目标，在已发布数学成果中填写调用、参数与缺失前提，先准备并审阅完整候选，再确认独立检查。候选、检查中状态与固定回执可刷新恢复，原运行与验收不变。 |
| 明确评审负责人 | 支持认领、指定与移交评审，作者补充后可重新送审。个人待办只进入负责人的收件箱，新一轮送审重新进入待办；作者不能评审自己，未获移交不能接管别人的评审。 |
| 面向读者的分享 | 新分享快照包含已记录的前提、任务依赖、推导和精确版本，以及对当前证明重新核验成功的已有审核讲解。读者可逐步阅读、对照目标变化与源码、交互查看路线，并从节点回到对应步骤。旧快照仍可阅读原证明与源码声明路线。 |

这些能力面向通用题目与已保存的研究记录。缺少推导或讲解时显示现有内容与缺失说明，不生成虚构步骤。任务检查与完整原题独立验收分别展示；自然语言形式化后的通过明确对应 Lean 陈述，并保留题意确认方式。

草稿保存在本机浏览器，不跨设备。阶段结论、试用候选、回执与评审归属保存在账号数据内，沿用账号删除与当前权限检查。借用的项目证据撤权后停止读取。Library 试用在检查前后核对成果、任务、源码提交、环境和权限，不能把试用通过当作原题验收。

分享在创建时冻结，既有链接不会自动纳入后来生成的讲解。新分享只收录既有审核文档，不额外调用模型；公开投影不包含账号、服务地址、Key、运行日志和内部 Agent 对话。
