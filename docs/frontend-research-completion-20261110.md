# 研究工作区产品补全 · 2026-11-10

本轮完成八项已确认的产品补充，沿用现有品牌、题目身份和数学验收流程。变更位于 `feat/product-continuity` 工作区，未提交、推送、合并或部署。

## 已完成的用户路径

1. **个人研究接入项目。** 题目页可核对原题后创建私有项目，带入精确源码、证明环境和所选运行。分步请求持久化去重，途中失败后重试不会重复创建。原个人预算可继续使用；若项目关联了多份不同预算，先选择来源，保留原记录。
2. **未提交内容与草稿收尾。** 指导、数学/源码批注、线程回复、评审意见与补充按账号和精确任务范围保留。切节点、关抽屉、刷新后可恢复。账号草稿提交后关联实际记录并归档对应版本，同时保留并行分支和提交期间的新编辑；可恢复、丢弃。
3. **统一消息入口。** 我的研究提供待决定、待回复、未读进展摘要。工作区收件箱与原通知共用已读来源，进展不计入待办。批注提醒直达原运行、任务版本和线程；候选评审批注自动展开对应提交。
4. **一个路线工作区。** 当前尝试和全局轨迹在同一区域切换，保留所选步骤及其版本。可沿依赖查看推导、固定源码与检查，再在该步骤参与指导、候选和讨论。已修复切回当前尝试时画布恢复旧节点的问题，标题公式使用现有数学渲染器。
5. **Library 试用历史与复用。** 可按运行、成果和状态找回候选、固定库、依赖与检查回执。历史目标变化后仍能读取已获授权的旧证据；重新试用保留同一任务并选择当前版本。原运行所有者可将已检查候选与固定库准备为新尝试草稿，由本人核对模型和预算后启动。
6. **成果交付。** 通过验收的题目在同一面板提供讲解、公开只读分享、停止分享、完整档案下载、Library 整理以及简报预览和导出。创建分享先展示公开范围并要求确认；只有运行所有者可操作完整档案和分享。
7. **私人结论引用到项目。** 本人明确选择一份阶段结论后，可创建项目议题，保留作者、定稿文字、路线与检查版本。其他私人结论、私人尝试列表和个人用量不会附带共享。同行可读取冻结证据并继续讨论。
8. **帮助、版本和诊断。** 工作区和指南展示真实前端构建摘要、构建时间、发布提交与服务状态。复制前可预览诊断内容，反馈自动携带已加载版本。诊断不含账号、Key、服务商地址或私有路径。检测到前后端版本变化时提示先保存编辑再刷新。

## 验证与边界

使用临时本地 HTTP 服务、隔离账号数据、录制观察和受控运行器验证。没有调用真实模型、Lean、外部邮件或生产账号。局部检查通过仍不等于完整原题验收。

- 根目录、Web 服务端、客户端、preview 和官网类型检查。
- 聚焦单测覆盖项目接续、精确身份、幂等与中途重试、草稿分支、权限、预算、Library 历史、统一消息、路线和翻译。
- 中英文桌面与手机浏览器覆盖草稿恢复、提交期间新编辑、归档恢复、提醒定位、阶段结论引用、试用复用及显式启动。
- 题目与全局轨迹原有回归覆盖尝试比较、人工决定、历史源码、变化摘要、键盘操作和读后状态。
- Web 构建与独立运行时构建通过；CLI 仍不依赖 Web 服务。

最终命令结果、报告摘要和文件校验值见 `out/product-continuity/research-completion/verification.json`。截图和报告以该索引引用的成功记录为准；排错截图不代表最终页面。

## 发布交接

增量基于本轮开始时的实际文件快照 `baseline.json` 与 `baseline-source.tar.gz`，而非仅基于 Git HEAD。共享工作区含既有未跟踪文件，因此交接同时提供逐文件前后 SHA-256、可应用补丁和本轮源文件归档。

发布会话应在已包含前轮 research-depth 冻结增量的独立集成分支上核对本轮前置哈希，应用 `increment.patch`，重新构建并进行部署检查。不要直接吸收整个脏工作区。此包不包括其他会话的官网改动或生成的证明验证日志。
