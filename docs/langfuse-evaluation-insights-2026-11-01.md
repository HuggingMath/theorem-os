## 1. 核心判断

**对 TheoremOS 最有价值的启发，是把现有证据和评测工具组织成持续改进循环：实际运行 → 人工分析失败 → 冻结回归样本 → 对照实验 → 独立验收。**

项目已经具备这一循环的大部分基础：S1 持久档案、固定 S3 验收、贡献流诊断、模块配对对照，以及形式化语义盲审的准备、执行和计分流程。[R1–R7] 因此，优先工作应是建立可重复执行的分析与决策流程，复用已有工具；现阶段不需要为了采用这套方法引入新的常驻服务。

最关键的数学领域区别是：**Lean 核验、原题语义忠实度、研究效率、自然语言解释质量，分别回答不同问题。** 模型审阅可为语义判断提供证据，但模型完成消息、审阅通过或局部定理通过，都不能授予完整原题的最终证明验收。[R1][R5][R8]

## 2. 原文中值得保留的方法

| 原文观点 | 对项目的直接启发 |
| --- | --- |
| 从人工阅读实际输出开始，识别具体失败，再自动化反复出现的检查。[L1] | 先阅读完整运行证据，明确哪里失效，再决定新增哪个评估器。 |
| 人工、代码、LLM 评估各有适用范围；代码能确定的属性优先用代码。[L1][L3] | 证明验收、版本绑定和收据完整性继续由宿主检查；语义忠实度另行审阅。 |
| 区分目标指标、护栏指标和运行指标；指标必须对应实际决策。[L2] | 解题率决定是否采用策略；证据完整性决定是否阻止合入；耗时与用量帮助定位成本。 |
| 每个评估器只判断明确的属性，采用二元或分类输出，并评估实际环境结果。[L3] | 使用“最终验收通过”“缺少证据”“语义不确定”等具体结果，避免综合质量分。 |
| LLM judge 需要用标注案例校准，检查各类别的错误，并持续复查。[L3][L5] | 审阅器自身也要做评测，尤其要看误放行、误拒绝和未知。 |
| 线上发现的问题应进入数据集，再由离线实验检验变更。[L1][L6][L7] | 将真实失败提炼为冻结案例，覆盖下一次模型、提示或模块策略变更。 |

这里的“线上”可对应用户实际启动的 CLI 或 workbench 运行，不要求把 CLI 变成 HTTP 服务。以上方法也不要求先部署 Langfuse。

## 4. 六项具体启发

### 4.1 将“是否解出原题”和“为什么没解出”分开

项目建议：保留 S3 作为最终验收，并在其外增加只读诊断。这样，策略可以改进任务组织和上下文，而实验仍接受相同标准的完整原题检查。[R1][R4]

建议按四个层次展示结果：

| 层次 | 回答的问题 | 证据及判断方式 |
| --- | --- | --- |
| 最终证明 | 当前冻结目标是否通过约定的完整验收？ | S3 结果、精确源码身份、Lean 收据；区分本地与官方。 |
| 语义忠实度 | Lean 声明是否表达了给定自然语言原题？ | 原文、实际类型与定义、片段对应、人工或校准后的语义审阅。 |
| 研究过程 | 哪个环节妨碍了贡献进入原题证明？ | 任务版本、assignment、贡献流、检查与消费者引用。 |
| 解释质量 | 自然语言说明是否忠实解释已检查的 Lean？ | 引用定位、目标状态、审计记录与人工评阅。 |

特别需要防止两种推理跳跃：可编译的声明可能翻译错题；对候选的反例也不自动证明翻译错误，因为原文可能本来就是假命题。现有审阅和 adjudication 模块已保留这一边界，应继续沿用。[R5][R6]

### 4.2 从完整运行证据建立失败分析，而非只看最后一条消息

Langfuse 的失败分析指南强调：先收集有差异的样本，记录可观察行为，再聚类为可行动的类别；抽样应包括成功和失败。[L4]

项目建议：第一轮人工阅读约 30–50 个可取得的真实运行或评测案例。若不足，使用全部可用案例，记录数量与覆盖缺口。按完整运行、审阅 case、解释 batch 分别建立队列，避免把这些粒度合并为一个失败率。

人工记录至少包含：精确输入身份、观察到的第一个问题、证据位置、尚不确定的部分、会因此改变的工程决策。下面仅是供复核的候选类别，不是预设发生率，也不应代替开放式阅读：

| 候选类别 | 可观察现象 | 进一步确认所需证据 |
| --- | --- | --- |
| 规划预算耗尽 | 尚无 peer 开始模型回合，运行已达到预算 | 请求级用量、调度与 turn 记录；不能把 dispatch 数当请求数。 |
| 原题路径停滞 | 原题仍未闭合，相关前沿停放或没有就绪任务 | 精确任务图版本、暂停决定、依赖与等待观察。 |
| 成果未被消费 | 已检查辅助声明存在，但没有可确认的消费者引用 | 检查收据、handoff 决定、集成记录与真实引用关系。 |
| 条件义务未闭合 | 局部证明在附加前提下通过，原目标仍缺证明 | 条件列表、相关任务版本与目标闭合情况。 |
| 源环境不可用 | 审阅无法取得与来源对应的展开观察 | 冻结工具链、库版本及 unavailable 诊断；不能据此标成语义错误。 |
| 声明语义偏移 | 量词范围、假设、结论或实际实例与原文有差别 | 完整命题语境下的比较；表示转换不能仅凭表面差异否决。 |
| 解释缺口 | 某个实质 Lean 步骤未解释，或解释与目标状态冲突 | 原始 Lean、逐步引用、goals 和审计意见。 |

这些方向可从现有文档与模块中找到案例线索。[R6][R8][R9][R10] 但本次没有读取那些远端运行目录，不能报告它们在当前总体中的频率。尤其是“没有消费记录”只能说明当前证据未确认使用，不能一概断言成果毫无价值。

### 4.3 用少量指标连接明确决策

采用 Langfuse 的目标／护栏／运行三类划分。[L2] 下表是建议优先稳定的口径；其中形式化审阅与实验统计已有实现，应复用。[R4][R5]

| 类别 | 指标与分母 | 指标变化后的决策 |
| --- | --- | --- |
| 目标 | **完整原题验收率**：符合该实验冻结身份及验收合同的通过尝试数／全部计划尝试数 | 决定是否采用策略；单列未执行、缺失、运行故障、预算结束和正常未完成。 |
| 目标 | **语义误放行率**：错误标签候选被 approved 数／全部错误标签候选数；另看 approved 中错误比例 | 检查审阅协议或证据是否不足。这里的“错误”依据给定标签，不能升级为数学真值。 |
| 目标 | **语义误拒绝率与 coverage**：正确标签被拒数／全部正确标签数；明确判定数／全部 cases | 防止通过大量 unknown 或拒绝正确转换来获得表面稳健。 |
| 护栏 | 原题、受保护声明、来源、环境、检查收据和恢复绑定是否违反合同 | 确认违反即阻止相关变更采用；不能让其他分数抵消。 |
| 运行 | **总用量及完整率**：上报 token；完整用量记录数／全部计划尝试数 | 判断预算配置与观测是否支持比较；不完整记录保留未知。 |
| 运行 | **分阶段耗时及覆盖率**：准备、求解、验证、最终验收分列；注明有效记录数 | 定位瓶颈，避免把省略验收或环境缓存差异解释成研究提速。 |

研究贡献消费、等待时间、重试和上下文省略适合作为问题定位明细。优先避免创建一个将这些现象加权为“Agent 质量”的总分。

统计时还应遵守以下约束：

- 报告计数与分母；分母为零时使用 `null`，不填 0%。
- 同时展示全体样本与有明确判定样本的结果；unknown 和缺失不能从主分母消失。
- 同一运行恢复后重新产生报告，不能把同一尝试重复计数；过期报告应识别出来。
- 请求数、调度数、模型回合数和 token 分列。累计 usage 快照不能逐条相加；已有记账完整性状态应一并保留。[R2][R6][R11]
- “更少 token”需要结合验收结果解释。较早失败的运行可能更便宜；成功样本中的成本也只是条件统计。[R4]

### 4.4 把真实失败变成回归数据，分别维护开发集与保留集

Langfuse 将数据集与实验连接到持续迭代。[L6][L7] 对本项目，建议维护三类互补的测试材料：

1. **确定性护栏与合同回归**：验证原题保护、收据身份、恢复、隔离与统计口径。沿用现有测试；fixture 结果表述为流程正确性证据。
2. **语义审阅校准集**：使用已有 `evaluate-formalization` 数据格式、盲审输入与 scorer，加入可核对标签来源的真实失误和人工变异案例。
3. **端到端解题集**：沿用 `compare` 的冻结题目、预算、隔离工作区和固定最终验收，回答策略是否提升解题表现。

第二类可以包含遗漏结论、添加假设、量词依赖变化、实例不一致等负例，也必须包含有效的等价表示、无害参数重排和边界条件处理等正例。[R5][R6] 单纯字符串不同不代表数学不等价。

沿用来源族分割：同一原题及其变体留在同一分区；开发时看过的失败进入开发回归集，不能再宣称是未见测试集。跨包准备数据时也要检查来源族重复。现有实现及文档已处理多项同源隔离约束，新增样本应服从它们。[R5]

建议每个新案例保留来源版本、标签程序、人工解释、输入摘要和所验证的失败模式。若怀疑上游标签有错，附独立复核材料；不得悄悄改写冻结标签后继续沿用原来的准确率名义。[R5]

### 4.5 校准现有语义审阅与解释审计

Langfuse 提醒，judge 本身也会出错，整体一致率会掩盖稀少类别的失误；校准需要逐类看混淆和具体分歧。[L3][L5]

项目建议先选择两个范围清楚的任务：

- 形式化审阅：对六项比较中的具体偏移能否正确识别，并允许有效等价表示。[R6]
- 解释审计：是否识别没有 Lean 依据的解释、遗漏步骤和错误目标状态，同时允许数学上正确的记号变化。[R8]

每个任务先人工标注一小批真实案例作为开发材料，冻结标准后在另外的案例上测量。报告误放行、误拒绝、未知、类别覆盖和分歧原因。若上游标签仅来自外部数据或模型，就如实标注；人类分歧也应保留待裁定状态。

v2 已经有独立回译与复审，informalization 也已有多个审计角色；建议评测这些机制的实际表现，而不是简单增加角色数量。同模型的多个新会话可能共享盲点，文档也明确指出新会话不构成统计独立性。[R6] 其结果不能替代人工校准。

### 4.6 用既有配对实验回答窄问题

项目已有冻结实验和配对统计。[R4] 建议下一轮优先选择能对应明确决策的问题：

| 实验问题 | 固定内容 | 主要读取结果 |
| --- | --- | --- |
| M4 可选上下文是否值得？ | 题目、模型、环境、预算、其他组件及 S3 | 完整验收、用量完整率、配对成本、上下文实际省略情况。 |
| 某个 M3 排序是否改变实际调度并改善结果？ | M5 及其他组件；仅改变明确的排序策略 | 实际 assignment 与执行顺序、原题闭合、等待覆盖。 |
| v2 的哪项机制改善语义审阅？ | 来源族分割、标签、模型与其余协议条件 | 误放行、误拒绝、unknown、实际调用与纠错成本。 |

现有 `critical-path` 方案同时改 M3 与 M5，只能解释组合效果；若要归因单个组件，需另准备单变量方案。[R4] 更换环境或构建时应明确其变化，保留全部失败与缺失配对。

涉及真实模型的预算校准和效果实验应在后续另行执行。本次阅读任务没有授权模型实验；历史实验文档也记录了暂停真实调用的约定。未来新运行按当前 `AGENTS.md` 使用本地 Sub2API、`deepseek-flash` / `max`；旧 Westlake `high` 方案只是历史实验配置，不能直接拼入新对照结果。[R4][R12]

## 5. 最小落地方案与优先级

建议先交付一轮**只读失败分析**，复用现有材料；下表均为后续工作建议，本次没有实施这些功能或标注。

| 优先级 | 工作 | 可检查的交付物与完成标准 |
| --- | --- | --- |
| P0 | 整理已有真实运行／审阅案例 | 样本清单及冻结摘要；说明来源、选择方式、成功/失败/未知覆盖，不把 fixture 混为真实模型运行。 |
| P0 | 人工阅读并归类 | 每例有观察、证据路径和待确定事项；归并出少量有明确修复决策的失败类别。 |
| P0 | 固定评测口径 | 复用现有 compare/scorer 输出；每张指标表附计数、分母、证据类型与验收方法。 |
| P1 | 将反复出现的失败纳入开发回归 | 优先补入已有测试或 formalization bundle；每例有标签来源和来源族归属。 |
| P1 | 校准一个最重要的语义判断 | 人工标注、独立验证案例、误判与 unknown 报告；暂不以其评分改变 S3。 |
| P2 | 执行一次预先冻结的窄范围真实对照 | 另行获得模型运行授权并校准预算后，使用现有隔离运行、固定验收与配对报告。 |
| P3 | 按团队分析需求选择可视化平台 | 只有需要多人标注、检索大量轨迹或持续看板时，再评估可选 Langfuse 导出。 |

如果需要新增工具，建议只做一个读取既有 inspection、comparison 和 scoring 结果的离线汇总入口。它负责案例索引、人工标注附件和证据导航；不重新解释验收规则，不写回旧 state，也不为未知事件补造时间线。[R3][R4][R5]

## 6. 是否接入 Langfuse

**建议先采用方法，再按需要增加可选的外部导出。** 官方外部评测指南支持在已有管道外计算评估结果，再关联写入 Langfuse。[L8] 对本项目，更合适的方向是离线导出器，或独立 workbench 服务的可选适配器。

建议的数据关系：run 对应 trace，角色/attempt/检查阶段对应 observation，审阅样本对应 dataset item，已冻结的实验方案对应 experiment run。映射时携带 run、task、源码、环境和评估版本身份；重导出使用稳定标识避免重复计数。

必须以仓库本地的冻结证据和 S3 合同为准；平台上的 score 只承担分析与展示。导出失败应只影响观测上传。CLI、`src/math` 和最终证明验收不能依赖 Langfuse 的服务、网络或凭据；可选 `apps/web` 仍然是独立服务。[R12]

默认只导出必要的摘要、指标和脱敏诊断，不上传 API Key、认证 profile、完整私有数学材料或未经选择的模型轨迹。原始证明、私有标签与审阅输入保持现有隔离约束；需要共享具体样本时再明确选择内容。

## 7. 需要避免的误读

- **只有验收通过的历史证明包，不能推算当前版本从零解题成功率。** README 已说明包含前身成果、继续运行和环境迁移。[R13]
- **预设回放通过说明管道可工作，不能测模型能力。** 形式化 replay 与来源为 preset 的评分已有明确标记。[R5][R6]
- **语义标签一致率不等于数学真值、生成准确率或最终证明验收率。** 这些目标在 scorer 中已明确分开。[R5]
- **引用存在不等于因果收益。** 检查到当前证明确实引用一个声明，可以确认引用；要判断知识复用是否提升解题，仍需对照。[R3][R10]
- **未知不可填成成功、失败原因或零耗时。** 旧日志覆盖不足时应保留未知；故障类别及缺失记录单列。[R3][R9]
- **确定性检查需要明确范围。** Langfuse 所说代码检查的稳定性适用于固定输入和条件；项目的 Lean 进程仍可能超时、被取消或缺环境，必须保留实际观察与故障状态。[L1][R1][R6]
