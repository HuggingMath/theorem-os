# 从已验收的 Lean 证明生成 LaTeX 论文初稿

## 目标与首轮交付

从 TheoremOS 已通过独立验收的 Lean 证明出发，生成一份数学读者可以独立阅读、作者可以继续编辑的论文初稿。首轮从 Web 的已完成运行中选一个已验收的目标定理，下载包含 `template.tex` 和 `main.tex` 的 LaTeX 源稿。PDF 编译、预览和下载放到下一轮。

初稿按数学论证组织。短证明用标题、定理和证明即可。较长的证明可以用摘要、引理、章节和交叉引用来说明推导结构。相关工作、原创性和文献引用需要有作者提供或确认的依据。

## 模板和正文

| 文件 | 内容 | 更新方式 |
| --- | --- | --- |
| `template.tex` | 文档类、字体、版心、宏包，以及定理、引理和证明环境。通过 `\input{main}` 载入正文。 | 预先维护并记录模板版本。导出时附上生成当时使用的版本。 |
| `main.tex` | 标题、按需添加的摘要和章节、数学陈述与证明、公式和交叉引用。 | 写作、审阅和修订只处理这个文件。作者拿到源稿后可以直接编辑。 |

`template.tex` 是后续编译入口。`main.tex` 是文档体片段，可以使用模板提供的环境和标准 LaTeX 公式命令。文档类、宏包加载和外部文件引用由模板管理。同一个模板可用于多篇初稿，同一篇正文也可以搭配提供相同环境的其他模板。

## 写作与审阅流程

1. **准备输入。** 从已验收记录中取目标定理、最终 Lean 源码及验收结果。用户的原题或已确认的陈述可以帮助选用自然的术语。已有讲解可作为写作材料，缺失时直接从已验收的 Lean 证明开始。遇到关键库引理时，提供其声明和必要上下文。[现有证明讲解流程](informalization.md)
2. **写正文。** 写作会话直接产出 `main.tex`。保留定理的对象、量词、假设和结论。可以调整叙述顺序、合并辅助引理，或用读者熟悉的论证替代 tactic 展开的推导。公式符号和术语在全文保持一致。正文无需标注 Lean 行号或逐步对应关系。
3. **审阅。** 独立审阅会话先通读正文，再对照已验收的目标和必要的 Lean 上下文。检查陈述是否准确、改写后的推导是否完整、引理的使用条件是否满足，以及符号和交叉引用是否清楚。Lean 验收记录证明形式版本通过检查。论文审阅结论记录的是对这份正文的判断。
4. **修订和导出。** 写作会话根据具体意见修订 `main.tex`。导出前检查正文片段的结构、标签和引用，例如重复标签、未定义的内部引用以及误放在正文里的导言命令。仍有数学疑点的版本标为待审，并保留具体意见供作者继续编辑。首轮结构检查的范围以源稿为限，实际编译结果在 PDF 阶段验证。

## 接入现有仓库

Web 入口可以放在已通过独立验收的运行页，作为独立的论文初稿任务。每份初稿内部记录运行 ID、目标声明、Lean 源码的 SHA-256 和模板版本，方便恢复并确认改写所依据的版本。现有 Web 讲解入口要求原运行使用特定模型。论文任务有自己的模型配置，因此也能从使用其他模型的已验收运行开始。[现有 Web 讲解入口](../apps/web/server.ts#L258)

证明材料的整理和初稿的数据契约可以放在 `src/math`，生成与审阅的执行可以放在 `src/solver`。Web 负责入口、作业状态和下载，独立验收记录继续作为论文任务的上游输入。

## 首轮验收

用运行 `ad5f6fdf-59f0-45de-be6a-ea9da6b6d63e` 验收首个样例。该运行证明了每个不小于 $5$ 的素数 $p$ 都满足 $24 \mid p^2-1$。正文可先指出 $p$ 既非偶数，也不是 $3$ 的倍数。于是 $p-1$ 和 $p+1$ 是相邻偶数，其中一个是 $4$ 的倍数，所以 $8\mid (p-1)(p+1)$。再由 $p\equiv\pm1\pmod{3}$ 得到 $3\mid p^2-1$，最后用 $8$ 和 $3$ 的互素性合并。这里把 Lean 的模 $8$ 枚举改写为因式分解和整除论证。

- 读者只凭初稿就能读通证明，包括 $p\geq 5$ 的用途、两个整除结论和互素合并。
- 审阅能识别漏掉素数假设、遗漏互素性或跳过关键推导的故意错误，并给出可定位的修订意见。
- 交付包含两个可编辑的 `.tex` 文件。修改或重新生成正文时，`template.tex` 的内容保持一致。
- 再用一个含多个辅助引理的已验收证明检查章节安排、引理引用和公式编号。
