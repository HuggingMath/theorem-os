# 网页研究工作台

`apps/web` 提供独立网页和 HTTP API，通过 Docker 启动一次性的求解 worker，复用现有 `runSolver()`、原题固定机制和最终 Lean 验收。CLI 不依赖此服务。

网页新任务统一使用 **TheoremOS 数学环境**：Lean 4.33.0、Mathlib `db584cd6d46c92f209a44c0f1c829460d327499d` 和 `theorem-os/core` 固定发布库（53 个模块）。自然语言、Lean、模板和普通草稿都使用这个环境；证明、形式化和预检查 API 省略 `environment` 时也选择它，内部标识仍为 `mathlib`。

形式化沙箱校验库的构建收据、源码和 `.olean`，再提供只读副本；查库 API 同时返回 Lean、Mathlib 和自有库声明的真实类型与导入模块。候选显式导入的自有库依赖闭包会进入宿主编译证据，证明交接继续使用这份冻结源码。每道题按需导入，避免为普通编译加载全部模块。

已冻结的任务、未确认的提交及历史证据保留原环境和请求身份，包括 `standard`。旧客户端显式提交 `standard` 仍兼容；曾省略环境并获受理的请求使用原请求编号重试时，也返回原任务，已删除任务返回 410，不重新创建。网页新建入口不再提供该选择。CLI 和历史基准的环境选项保持独立。

## 本地启动

需要 Linux、Docker Engine / Compose，以及允许非特权用户创建用户命名空间的宿主机。Mathlib 运行还需要可用的 `/dev/fuse`。每个容器上限为 2 CPU，Mathlib 内存上限 8 GiB、标准库 4 GiB，默认一次运行一个任务。建议为每个并发 Mathlib 运行预留 30 GiB 可用磁盘；冷准备会按依赖体积约三倍检查磁盘余量。

首次构建需联网下载 Bun、Codex CLI、固定 Lean 工具链、Mathlib 源码和预编译依赖，镜像较大，下载可能较慢。构建会复用下载缓存、重试失败下载，并执行完整 Mathlib 构建和 `import Mathlib` / `ring` 探针。

worker 还通过 `scripts/build-pantograph.ts` 从固定 Pantograph commit `0ee70917fb93a5421157119362ecde806a4d881b` 构建 `repl`。脚本校验源码归档 SHA-256，使用镜像已安装的 Lean 4.33.0 重新编译，并将可执行文件、Lean 库、许可证、构建来源和逐文件摘要清单安装到只读的 `/opt/theoremos-pantograph`。上游源码的 4.33.1 工具链选择只在临时构建目录改为 4.33.0；题目和 Mathlib 的固定环境保持原样，运行时不会下载或构建后端。

目前仅 Mathlib worker 注入 `DEEPSCIENTIST_MATH_PANTOGRAPH_MANIFEST`，由运行时校验产物并把后端摘要纳入运行身份。Agent 通过独立工具包中的 `proof-search` 对已物化、类型闭合的普通 helper lemma 执行有预算的 tactic 搜索。候选和断点是 advisory，仍须经过 ready、停写、冻结、独立 Lean 检查、集成和 S3。标准库 worker 没有 sealed/FUSE 环境，因此保持后端未配置，调用会返回 `proof_search_backend_not_configured`；未放宽其设备或文件权限。

```bash
git clone https://github.com/HuggingMath/theorem-os.git
cd theorem-os
THEOREMOS_SOURCE_COMMIT=$(git rev-parse HEAD) docker compose -f apps/web/compose.yml build worker web tex
docker compose -f apps/web/compose.yml up -d web
docker compose -f apps/web/compose.yml ps
```

也可拉取 GitHub Actions 发布到 GHCR 的镜像。`main` 推送和面向 `main` 的 pull request 运行验证。推送 `v*` 标签或从 `main` 手动运行 `images.yml` 会先验证同一提交，再发布 `ghcr.io/huggingmath/theorem-os-web`、`ghcr.io/huggingmath/theorem-os-worker` 和 `ghcr.io/huggingmath/theorem-os-tex`。镜像标签使用完整 commit SHA。旧 `likc1606` 地址用于读取构建缓存。worker 包含完整的 Mathlib 环境，首次拉取较慢；tex 镜像只包含 XeLaTeX 编译环境。

```bash
export THEOREMOS_IMAGE_TAG=<完整的40位提交SHA>
docker compose -f apps/web/compose.yml -f apps/web/compose.ghcr.yml pull worker web tex
bun scripts/web-operations.ts images --commit "$THEOREMOS_IMAGE_TAG"
docker compose -f apps/web/compose.yml -f apps/web/compose.ghcr.yml up -d --no-build web
```

`THEOREMOS_IMAGE_TAG` 必须指定完整提交 SHA，web、worker 与 tex 使用同一版本；没有默认 `main`。CI 先通过测试，三个镜像均发布成功后才上传发布产物。维护、排空、备份恢复、监控和回滚命令见[运维指南](web-operations.md)；首轮用户试用见[任务与反馈表](web-release-trial.md)。runner 以 `--pull=never` 创建运行容器，因此 worker 和 tex 镜像需要先拉取到本机。GHCR 包首次发布后默认私有；需要匿名拉取时，在仓库 Packages 设置中把三个包改为 Public。

浏览器打开 <http://127.0.0.1:8787>，首页显示问题输入框；不预填例题，也不要求先导入原题。TheoremOS 数学环境与 high 是默认值。输入框的「设置」可填写 Key；账号已有 Key 时直接使用。首页的输入框在页面中部，设置向下展开，不盖住标题和输入框，屏幕太矮时滚到可见；对话中的输入框在底部，设置向上展开。在输入框里打字时边框加粗为 2 像素，颜色与静止边框、页面和输入框底色的对比度都在 3:1 以上（浅色 3.68 / 5.05 / 5.42，深色 3.65 / 6.42 / 5.94）。新对话清空输入，普通刷新保留当前标签页的草稿，顶部 Logo 和「新对话」均回到首页。

输入框优先展示题目，参与方式收在下方紧凑菜单中。默认沿用「共同推进」，题意与初始计划由用户确认；可明确切换为「自动推进」。预算默认留空表示不限，选择与预算随当前草稿保存。

- **默认版**：直接输入自然语言或 TeX 原题，发送后直接生成 Lean 陈述，编译通过后立即提供代码并启动证明研究，语义审核在后台并行进行；最后显示证明与独立验收结果。
- **进阶版**：通过输入框旁的 Lean 入口直接编写、粘贴或导入形式化题目，只有此模式校验源码。自然语言与 Lean 草稿分别保留。

首页和已有对话使用同一个持续挂载的输入框。第一条消息创建形式化和证明任务；后续发送作为追问，由服务端读取原题、当前 Lean、研究进展以及最近八轮问答作为上下文。会话消息持久化在账号目录，通过 `?chat=<id>` 恢复；`?run=` 和 `?sample` 旧入口继续可用。侧栏先列对话，解题任务可展开查看。Enter 发送、Shift+Enter 换行，中文选词不触发发送；触摸设备保留回车换行。

草稿同时保留当前光标、选区方向和输入框内的滚动位置，按会话独立保存。切换会话或在当前标签页刷新后可接着原处编辑；后台更新不重置位置，也不会抢走焦点。点击「追问这一步」或撤回引用时，光标仍移到问题末尾，方便继续补写。

对话支持 Markdown、行内和独立公式、Lean 高亮及代码复制；长代码默认折叠，可展开完整内容。公式资源随页面构建，不依赖外部字体或公式服务。回答在生成过程中逐步显示并保存，停止、服务重启或失败均保留已保存的部分内容；刷新只恢复会话，不重新请求模型。阅读位置按会话中的消息及偏移保存，向上阅读时新回答不会抢走位置；「回到最新」恢复底部跟随。没有回答或任务在进行时，页面每 30 秒核对一次当前对话，回到标签页或网络恢复时立即刷新；读取失败的提示在下一次读取成功后消失，发送失败的提示保留到下一次操作。对话列表未能加载时显示原因和「重试」，不显示为空列表；请求超过站点频率限制时提示稍后再试。

路线图、原题与 Lean 对照、候选源码或验收证明在独立结果面板中打开；窄屏全屏查看并可返回对话，切换不会丢失输入。原题面板包含完整原文、Lean 声明和下载入口。默认由一个独立审核会话在后台比较原题与编译陈述，状态、六项检查和具体修改意见自动更新；审核中即可下载、确认或继续证明，证明结束后仍会更新审核结果。审核不改写代码或中断证明；失败、未知和中断单独显示。旧审核记录仍可查看回译、对应关系与完整审核。

任务状态下面永远有一份「解题过程」，按 形式化原题 → 证明 → 独立验收 三段列出：形式化写了几轮、编译过几次及修正的编译问题；旧审核记录还显示审核反馈。证明阶段每个 Agent 一行，写明它当前在做什么、自查与平台检查的结果和轮数；最后是在干净环境里重新检查完整原题。进行中默认展开、最新一轮显示在最前，结束后收成一行（`解题过程 · 18:02 · Lean 检查 9 次 · 尝试 5 次`），点开仍有完整记录。宽屏在任务开始时自动在右侧打开实时工作区：当前正在写的 Lean 文件、Lean 报错所在行（错误直接标在该行下面，并给出第几行的跳转）、以及每次 Lean 检查的时间与结果；点击列表中的某次检查会切到那次检查保存的文件，点击对话里的检查行也会跳回这里。窄屏只在对话内保留清单，检查记录就地展开。状态行同时给出已用时间、Token 和「停止解题」。这些记录只属于运行者本人，分享页不显示。

公开解题记录突出角色和记录标题，状态单独显示，时间保留在记录头部。Lean 陈述与每次检查保存的源码使用统一的代码块，提供语法高亮和全文复制，长行按可用宽度换行；详细记录中的代码默认显示全文。普通对话中的长代码仍先显示 18 行，可继续展开，复制时始终保留全文。

记录中的版本缩写可点击或用键盘展开，查看并分别复制完整任务版本、候选提交版本和源码摘要；手机端长标识自动换行。当前、历史与未确认版本保留各自标签，缺少版本时不补造信息。版本详情的展开选择独立于数学说明，轮询和切换会话后保留；本地进展搜索也支持完整版本号。
任务状态下面优先显示「数学进展」：已检查且无未决条件的引理与目标、当前任务、实际障碍和已保存的题意或研究记录。条件证明与暂停路线分别保留原状态，研究记录不代表最终验收，也不将观察心跳当作数学结果的时间。引理可直接打开对应任务路线。

新研究通过独立验收后，服务器自动为全部原题目标排队生成讲解，沿用这次解题的凭据和模型；自然语言原题的含义审核尚未完成时先显示等待，审核通过后开始生成。对话直接显示排队、写作和审核进度，完成后自动展示概览、结论与证明步骤；多个目标可逐一选择。讲解语言随提交时的界面语言冻结，切换界面语言时可继续阅读已有语言的讲解。生成失败保留证明与验收结果，可在讲解页查看原因并重试。读取或刷新不会新建模型任务，也不补跑历史记录。辅助定义可展开，报告、代码、下载与分享入口继续可用。

完整「解题过程」接在数学内容之后，按 形式化原题 → 证明 → 独立验收 三段列出：形式化写了几轮、编译过几次、审核退回改了什么；证明阶段每个 Agent 一行，写明它当前在做什么、自查与平台检查的结果和轮数；最后是在干净环境里重新检查完整原题。进行中默认展开、最新一轮显示在最前，结束后收成一行（`解题过程 · 18:02 · Lean 检查 9 次 · 尝试 5 次`），点开仍有完整记录。宽屏在任务开始时自动在右侧打开实时工作区：当前正在写的 Lean 文件、Lean 报错所在行（错误直接标在该行下面，并给出第几行的跳转）、以及每次 Lean 检查的时间与结果；点击列表中的某次检查会切到那次检查保存的文件，点击对话里的检查行也会跳回这里。窄屏只在对话内保留清单，检查记录就地展开。状态行同时给出已用时间、Token 和「停止解题」。这些记录只属于运行者本人，分享页不显示。

`test:web-solve-process` 用本地模拟的形式化与运行验证上述清单、宽屏自动打开实时工作区、Lean 报错标在出错行下、选中的检查、关闭与重新打开，以及结束后的收起；覆盖桌面对窄屏两种宽度，不调用模型。

消息提到当前任务中真实存在的定理时，附上对应引理入口。点击后路线图定位到该任务节点，可继续查看 Lean 源码与检查记录；尚未集成的引理打开对应任务版本的已保存源码。返回对话恢复来源消息、焦点和草稿；不会把模型随口提到的名字编成路线图节点。

追问用于解释和讨论，回答本身不执行 Lean 或修改原题。运行中可在输入框点「发给证明任务」，或把已有追问「作为证明要求」，选择任务负责人或具体引理后提交；原文、目标版本、观察身份和真实投递回执保存在会话中。排队、送达、暂缓或拒绝状态随原回执更新；结果未知时只核对原提交，不换 ID 重复投递。任务版本变化时须核对内容并确认新版本。修改题目创建新任务，不覆盖冻结原题。「停止回答」只中止当前问答，「停止解题」使用任务取消流程。切换或新建会话不会取消后台研究。消息回答完成不表示证明通过，只有完整原题的独立 Lean 验收通过才显示通过。

公开解题说明中的「追问这一步」将所选说明、前提、Lean 陈述及记录的完整任务或候选版本放到讨论草稿中，保留原有问题文字。引用是点击时的快照，详情收起时也会带上已保存的数学内容；重复点击同一份内容不会重复插入。输入框聚焦到草稿末尾，进展暂停自动跟随，阅读位置与展开选择保留。引用可直接编辑，刷新或切回会话后仍在；点击引用只准备草稿，由用户发送。证明指导模式下隐藏此入口。

暂停进展跟随后，「查看最新进展」显示当前筛选范围内新增的记录数，手机端也显示数字。同一条记录的流式更新不重复计数，搜索、折叠或切换会话保留计数；点击该按钮或手动滚到进展底部后恢复跟随并清零，后台更新不抢走阅读位置。

进展搜索支持「上一个匹配 / 下一个匹配」和 Enter / Shift+Enter，按完整结果列表循环定位，包含较早且尚未挂载的记录。选中后显示当前位置，标记只出现在命中片段中，保留详情的展开选择。轮询与切换会话保留所选记录，修改关键词后重新选择；中文选词的 Enter 不触发跳转，关闭搜索或按 Esc 回到搜索前的阅读位置。

从命中片段打开「查看前后记录」后，工具栏提供「返回搜索结果」，恢复关键词、筛选、所选记录及结果阅读位置；也可在进展区域按 Ctrl / Cmd+F 返回。手机端复用原搜索按钮位置，折叠、轮询和切换会话保留入口。定位后的记录继续更新时，保留对话及进展内的阅读位置。返回后的搜索仍可继续定位，关闭后回到最初阅读位置；主动恢复最新进展后结束这次搜索往返。

形式化与证明使用首次提交所选服务商、模型及 Key（或账号已有 Key），刷新不重提。形式化未编译通过时不启动证明；证明排队失败可点「继续证明」，复用已冻结证据，只创建一次证明，不重新扣形式化次数。Key 不随浏览器草稿或会话消息保存。自然语言输入不要求填写 Lean 源码。

后台审核使用单独的队列和执行位，不占用生成或证明的执行位。预算留空或为 0 时不限时间和 Token；显式设置上限时，审核使用形式化剩余 Token 和原任务截止时间。服务重启将未结束的审核标为中断，已编译代码仍可使用，不自动重新调用模型。删除形式化记录或删除账号数据会停止对应审核；晚到的回调不会恢复已删除记录。分享页只报告所分享陈述的编译和证明事实，审核详情保留在运行者自己的形式化记录中。

`test:web-chat-session` 使用临时服务与本地模拟 Responses 服务，验证连续追问、历史/返回/刷新、空闲时的慢速核对、列表加载失败与重试、同一个输入节点、公式与代码、部分回答持久化、失败与停止、阅读位置、原题对照，以及对话中设置向上展开。`test:web-chat-artifacts` 验证消息到真实引理、Lean 源码与返回位置，以及定向证明要求的持久投递回执。两者覆盖桌面与移动端；`test:web-natural-first` 验证两种输入入口、例题、草稿、语言布局，以及首页设置在输入框下方展开且不出屏。测试不调用真实模型。

独立的 `formalize.html` 页面保留手动生成、核对、确认及带入进阶版草稿的工具。修改原文或环境后不能把旧确认结果当成新题使用。

新建研究首个例题是「自然数加零」，与首轮试用卡一致：证明对任意自然数 n，都有 n + 0 = n，只需 Lean 标准库。其后保留平方和公式、有限维柯西–施瓦茨不等式、素数无穷性和三次舒尔不等式四组 Mathlib 例题。五题均有完整中英文自然语言原题与对应 Lean 陈述。首页「试试例题」展开自然语言例题选择器，选题填入原文与环境。选题本身不调用模型。已有 Lean 模式内保留对应 Lean 例题，以及自然数加法、命题逻辑和实数多项式三项入门示例。

例题数据统一维护在 `apps/web/problemExamples.ts`。「自然数加零」使用 `theorem add_zero_trial (n : Nat) : n + 0 = n := by sorry`，模板及替换为 `by rfl` 的证明均通过固定 Lean 4.33.0 标准库检查；其余四个 Lean 声明已通过固定 Mathlib 环境的离线编译检查。界面中的例题证明位置保留 `sorry`，声明可编译不表示证明已完成。`test:web-formalize` 覆盖两种入口、中英文原文、替换确认、环境匹配、显式提交和窄屏布局。

提交后停留在对话内，点击结果入口查看「研究协作」。任务依赖、Agent 分工、源码与检查回执、人工指导、计划修改和知识检索均读取实际运行；尚未建立计划时显示等待状态。独立并行运行也可查看已有观测，协作计划编辑需要运行时提供对应计划。

工作台顶栏、欢迎页和命令面板提供「经典题库」入口，所有账户均可查看同一份 OpenAI Math 本地验收通过的解答，包含原题、最终 Lean 证明、辅助模块、验收证据和历史解题过程。浏览与下载无需 API Key，也无需先创建研究。题库是随 Web 镜像构建的共享只读档案，不计入个人运行记录或配额；个人研究仍按账户隔离。题库支持中英文和按题下载，返回工作台保留原标签页中的草稿与研究。

定理页默认列出全部已解决的 OpenAI 题目，按完成时间排序，并提供名称与声明搜索、领域筛选、解题过程、源码和验收证据入口；当前快照共 18 道。「研究项目」保留协作研究、创建题目和陈述版本等操作。题目目录使用构建生成的轻量 `classics/data/index.json`，完整源码与研究过程按需加载。Library 默认展示可复用的 Lean 数学库、模块和接口，「共享数学库」展示已发布研究资源，Agent 与 Skill 保留独立分类。旧 Library OpenAI 链接转到定理页并保留搜索与领域条件。

两个目录在桌面按领域侧栏与单列内容浏览，手机改为横向领域筛选。定理页以「阅读解答」为主要入口，可按完成时间或题目名称排列，清除筛选后焦点回到搜索框。Library 使用紧凑分类与来源导航，模块提供复制导入语句；详情支持当前模块内的接口搜索及引理、定义筛选，不重新读取完整源码。

题库数据来自 `research/openai-math/`，与官网档案共用校验和构建模块。更新时先运行 `bun run import:math-results /path/to/campaign`，再执行 `bun run build:web`。导入器同时保留当前和历史验收通过的结果：后续未成功的运行不会覆盖已解决题目，历史结果仍绑定原成功运行、源码 commit、证明摘要与 Lean 收据，并校验结果和状态快照的摘要。Docker 部署需重新构建并更新 Web 镜像，宿主机的 `out/web` 不会替换容器内的文件。全量题目目录的浏览器回归为 `bun run test:web-openai-problems`，经典题库回归为 `bun run test:web-classics`；均使用本地测试服务，不调用模型。

页面通过同一份运行列表同步状态和任务观察，不再为协作面板重复自动读取观察。`GET /api/runs/stream` 使用当前会话的 Cookie 建立 SSE 连接，在运行或观察变化时发送 `runs-changed` 版本通知，再由页面通过原有列表接口读取数据。通知仅包含当前会话的列表版本，不包含运行正文或密钥；连接建立和重新建立时立即发送当前版本，同一批同步变化合并为一次通知。

列表支持按会话隔离的 ETag 条件请求：状态未变化时返回 304，无需传输和重绘完整记录。读取期间收到的新通知会在本次读取结束后再次核对，不并发读取或漏掉后续变化。实时连接正常时每 30 秒额外核对一次；连接不可用时自动回退到运行中每 1.8 秒、空闲时每 5 秒的轮询，指导与计划操作仍可使用。SSE 通过浏览器自动重连，不重放创建、取消或人工指导等写入。

页面隐藏时关闭实时连接，返回时重新连接并立即读取列表；网络恢复或会话重建后也会重新核对，旧连接的响应与通知不会更新当前页面。手动刷新运行记录仍读取完整列表，「刷新观察」单独读取当前研究。

指导与计划修改的提交和查询回执会附带服务端当前保存的观察，收到后立即同步任务图、计划版本和运行缓存。提交响应和回执查询均按相同命令 ID 核对运行时记录：已记录应用、拒绝或指导投递时，返回该状态及相应记录；尚无匹配记录的 unknown 仍表示结果未确认。计划预览与正式提交使用相同的命令摘要，查询和重复提交也保持一致。迟到的列表或命令响应保留页面已收到的较新状态；命令确认与完整原题的证明验收分别判断。

输入区上方会提示当前缺少的提交配置，点击提示可直接前往对应字段。首次进入时需要填写 API Key；所有字段满足本地格式检查后显示“提交配置已填写”，Key 与模型的可用性在实际提交时确认。空白任务、模型或密钥格式错误、超出字节大小和执行预算限制会在字段旁提示，修正后清除；这些本地检查不会创建任务或调用服务商。

网页默认使用宿主机已部署的 Sub2API 网关、`deepseek-flash` 模型和 `high` 推理强度，形式化与后续证明一致，API Key 填写该网关的访问密钥。OpenAI 保留为可选服务商；切换服务商后，请填写该服务商实际提供的模型，并选择其支持的推理强度。已保存的草稿和任务保留原配置，可在新研究配置中手动调整。

默认网关地址为 `http://host.docker.internal:8080/v1`。worker 启动时通过 Docker `host-gateway` 映射访问宿主机，因此网关的 8080 端口需要对 Docker bridge 可达。CLI 使用的 `http://127.0.0.1:8080/v1` 指向同一网关；在 worker 容器里，`127.0.0.1` 指向容器自身。每次 Sub2API 运行都会生成独立的 DeepSeek 模型配置，固定 131,072 Token 上下文并支持 `max` 推理强度。

## 数学协作流程

「研究协作」以数学任务组织证明过程。实线表示同一路线所需的前置任务，虚线表示可选择的证明路线；桌面可切换依赖图和任务列表，手机直接显示列表。可组合路线、任务状态和关键词筛选，关键词覆盖任务、类型、负责人和分组。界面显示匹配数量，空结果提供清除筛选入口；当前路线从计划移除时保留标记，等待重新选择。筛选不会改动检查器中的选择，所选任务不在结果中时提供明确提示和显示入口；历史合同保留记录版本。

选择任务后可查看完整类型、前提、计划依赖、实际记录的引用、条件性结果、阻塞、负责 Agent 和交付材料。列表中选择任务会直接定位详情，「返回任务列表」恢复原入口、筛选和阅读位置；宽屏依赖图保留卡片焦点，切换任务时将检查器滚回标题。视图选择和阅读状态按研究分别保留，轮询不主动跳转。Agent 面板显示固定角色、当前会话角色、任务和等待原因，点击任务可返回检查器。

固定分区导航可直接进入进展、任务、审阅、变化、Agent、交付、指导、记录和知识；手机使用单行选择器。点击「提供指导」、任务/Agent 指导或引用材料后，指导区提供返回来源的入口，恢复原来的任务版本、筛选、内部阅读位置和焦点。各次研究分别保留草稿和返回位置。

主动读取源码或检查回执时，立即定位材料区并展示加载状态，结果返回后原位更新，保留之后的编辑焦点。观察信息与手动操作反馈分别显示；轮询不会抹掉刷新失败或归档完成提示，归档成功后可直接「查看归档」。

「证明前沿」显示原始目标尚需推进的任务与缺失依赖，OR 替代路线分别展示，附上路线停放依据。数学阻塞显示机制、作用范围、状态和重开条件；等待新的数学输入时显示具体原因与关联任务。记录中的局部闭合不等同于完整原题通过 S3 验收。

「审阅与验收」集中展示声明一致性、固定候选审阅和完整原题的 S3 结果。可按任务、审阅状态和关键词筛选声明审阅，对照该记录保存的数学意图、Lean 声明、独立回译、假设、定义和摘要。回译完成仍须等待语义比较；请求修改的原因可能来自数学判断或协议故障，以保存的摘要为准。恢复后可能保留先前摘要，当前阶段以状态为准。任务检查器的「查看此任务审阅」可定位相关记录。

每份声明审阅展示审阅 ID、任务版本、声明快照摘要、采集 commit 和环境；不同审阅即使任务版本相同也分别保留。任务与依赖入口按记录版本读取当前或历史合同，缺失合同不以同名当前任务替代。声明或相关引用不变时，运行时可将已接受的审阅复用到新的任务版本，保留原审阅身份和采集提交；前端不按 commit 是否落后判断失效，也不把接受结论理解为重新审阅。声明快照摘要不关联普通证明源码或 Lean 回执。旧观测缺失的审阅字段明确标为未知。

候选 Reviewer 的结论固定到记录中的 commit 和源码摘要；该区展示最近保存的审阅对象，不推断它一定适用于当前源码。声明及候选审阅接受均不改变 S3 状态；只有运行完成且最终结果为 `evaluated_passed` 时展示完整原题验收通过。数学对照与摘要直接展示，完整身份可展开查看。「加入指导草稿」引用审阅的完整身份、观察归属和简短摘要节选，保留原草稿及接收方，不自动发送。轮询保留筛选、选择与阅读位置，同一审阅状态变化时保留未改变正文的内部滚动；所选完整审阅身份从观测消失或被复用到其他任务版本后，保留原选择并提示，须显式选择新记录。

「数学变化」按运行时实际记录的快照差异展示义务新增、局部闭合与重开、原始目标前沿、阻塞、OR 路线和提示性研究的前后内容，可按类型、关联任务与关键词筛选；任务检查器提供「查看此任务变化」入口。每侧的任务入口固定到记录自身的版本，合同未保留或版本未记录时保留未知。路线记录只含任务 ID 时不推定其历史版本。观察基线不把已有证明计为新闭合，局部变化也不代替 S3 验收。

运行时仅保留最近 64 条数学变化，此区显示本次观察的记录数量与最早、最晚生成时间，不宣称完整历史；没有新记录不能推断研究停滞。轮询保留筛选、选择和阅读位置，所选记录移出保留窗口后明确提示，不自动切换到其他记录。「加入指导草稿」追加所选变化的摘要、时间、前后快照与当前观察归属，保留已有文本和接收方，不自动发送。「下载所选记录」在浏览器导出原始条目、运行身份、观察引用与保留窗口范围；快照摘要不作为 Lean 源码摘要或检查回执。

「研究交付」可按 Agent、任务和关键词筛选，查看声明、前提、固定版本的依赖、未完成义务、完整研究发现及附带材料。Agent 的「交付」按钮与任务检查器的「查看此任务交付」可直接定位记录。轮询保留筛选、所选交付和阅读位置；普通研究笔记即使没有源码与检查证据也可完整阅读。

从交付或证明前沿打开任务时，按任务 ID 和版本读取当前或历史合同；历史合同标明版本，不计入当前任务进度，也不显示推定的历史调度状态。源码入口要求任务版本、commit、源码摘要及记录环境一致；检查入口还要求交付明确引用该回执，读取后再次核对身份。声明审阅和回译的声明快照摘要不作为普通 Lean 源码摘要。Agent 的原始文字引用仅按原文展示；本次观察未关联到材料时保留未知，不据此认定没有证据。

任务源码和检查回执绑定任务版本、commit、source digest 与环境。历史任务发生修改后，旧版本证据仍可读取；读取记录不重新执行 Lean，局部检查或条件性证明也不会改变完整原题的 S3 验收结论。观测显示采样时间、序号和覆盖情况；轮询更新保留当前任务、输入草稿和阅读位置，断线时保留最后一份观测。

在任务检查器打开源码后，可从同一任务实际保存的快照中选择基线和对照，查看逐行差异或完整源码。同一任务版本的不同 commit 也分别保留，两侧显示任务版本、commit、源码摘要、环境摘要和文件。轮询新增快照时保留已选两侧及阅读位置；切换任务后清除旧产物。只有一份快照时显示源码，差异超出展示预算时仍可分别读取完整文本。对比本身不执行检查，也不改变验收状态。

自由指导可发给 Lead、指定 Agent 或指定版本的任务。指导记录区分排队、暂缓、已投递与失败，显示投递对象及原因；已投递表示运行时接受通知，采纳与证明结果另行判断。指导不会直接修改任务合同。

每份指导最多 4000 字符。知识、数学变化或审阅引用若超出剩余空间，会保留原草稿和接收方并提示未加入；缩短草稿后可重新引用，不截断引用身份。

输入时显示当前字数；发送期间显示处理状态。断线、运行结束、等待观察、任务版本变化或原提交待核对时，输入区会说明无法发送的原因，草稿继续保留。

选择任务后，指导草稿固定到当时的任务版本。轮询发现版本变化时，展示草稿版本与当前版本，须核对内容并点击「确认当前任务版本」后发送；任务或 Agent 被移除时保留原目标，等待明确改选。每条已记录指导展示任务版本及其依据的观测序号和摘要。

指导提交响应丢失或结果未知时，保留原 ID、接收方、任务版本、内容与观测引用，并先只读查询命令回执。可继续编辑下一份草稿，原提交确认前不能发送第二份指导。「核对指导回执」不会重发；只有读取明确返回 404 时显示「重试原提交」，点击后再次读取，仍缺失才按原内容和 ID 重试。读取失败或已存 unknown 回执均不会触发重发。运行时明确拒绝会保留草稿并解除等待，传输或存储失败仍需核对；已有指导可按原 ID 读取，不因观测保留窗口过期而误报拒绝。各研究分别保留草稿和等待状态，迟到回执不会清空后续编辑；这些未提交草稿与待核对提交仅保留在当前页面，刷新前应完成核对。

「编辑计划」支持任务暂停/恢复、owner 和组 engineer 调整、任务及依赖增删、证明路线变更，也保留完整计划 JSON 编辑。先预览变化与受影响任务，再提交带 `baseVersion` 的计划。版本冲突时保留草稿，须显式重新核对基线；提交结果、host 应用状态、相关证明的重新检查分别显示。运行中的固定 Agent 人数及身份不在此处修改。命令响应不确定时按原命令 ID 查询回执，不自动创建第二份修改。

常用表单可新增研究、证明草图或引理，调整类型、负责人、目标、AND 依赖、前提、证明位置、任务分组和共享范围。「OR 证明路线」分别设置原始目标、收尾引理与路线前提；路线前提还须属于收尾引理的普通依赖闭包。「任务分组与 Engineer」可增删分组、指定 Engineer、调整组调度及轮次和并发上限。新增分组会保留隐式的默认 main 组；跨组依赖需要对应材料允许整个问题共享。原始目标的声明、文件和类型只读，不能由常用表单删除。切换研究或草图为引理时需补充精确类型；切回提示性任务时清除证明专用字段。既有负责人会保留，是否可接受仍由运行时校验。

删除仍被任务或路线引用的辅助任务、删除仍有成员的分组时，表单列出引用并保留草稿，先调整引用或迁移成员再删除。所有结构操作只改本地完整提案，修改后须重新预览才能提交；表单与高级 JSON 双向同步，JSON 无法解析时暂停表单编辑以保留原文。轮询不会覆盖正在编辑的合同。

计划提交响应丢失或状态未知时，页面先只读查询原命令回执。后续观察一旦记录同 ID 的应用或拒绝，编辑器自动确认并清除待核对提示，不需要手动刷新；重新检查的进度与各任务回执也原位更新，保留本地草稿、焦点和已展开的记录。关闭编辑器或切换研究后，重新打开会用当前运行的最新观察核对。

仍未确认时，可「核对提交回执」，查询不会重新执行命令。暂未找到回执时，可审阅原提交，再明确选择「重试原提交」：重试先查询，并保留原 ID 与原内容。期间继续修改的草稿单独保留，待原命令结果确认后再预览提交。不同研究的计划草稿、等待状态和回执分别保存；迟到的排队、未知或读取失败响应不会覆盖已观察到的应用结果与重新检查记录。

知识检索提供声明、前提、来源、源码、依赖和消费者，区分已记录检查的定理与 advisory finding。可以把引用加入指导草稿。新研究默认使用本账号最新的非空知识目录，并在创建时固定不可变 catalog digest；也可明确选择历史版本或选择不使用历史知识。基于旧运行继续研究时，未明确改选的目录沿用旧运行的固定版本；新环境仍需重新检查历史证据。运行结束或取消前，worker 会尝试导出实际成果，服务保存新 catalog 版本。「归档知识」另保存当前运行的观测、全部已记录事件、各版本源码、检查及命令回执，下载包带摘要和覆盖说明。归档成功或收到新的成果目录后，知识检索会更新可选目录；选择「最新知识目录」时更新当前搜索，明确选择的历史版本会保留。切换目录或搜索时清除旧详情，引用始终绑定实际查看的记录和目录。归档不是可直接恢复执行的 solver checkpoint。

Mathlib 题目还会自动检索随 worker 冻结的版本化 Lean 库目录，在普通 Lean 和已确认自然语言形式化两种证明入口安装最多四个相关模块及其依赖。目录保存公开接口，源码按摘要单独保存；检索后才读取选中模块。显式 `Submission.Library.*` 导入始终保留完整依赖闭包，原题源码字节不变。默认私有目录 `theorem-os/core` 的版本 `2902dec1e973bd70dad0444a8dc2320cf81d90fd-lean4.33.0-r4` 包含固定 Lean 4.33.0 / Mathlib 环境兼容的 53 个模块、1,964 条定理与定义接口。r3 的 50 个模块保持原有源码字节和完整模块元数据，其中包括 44 个上游模块，以及有限不等式、有限概率矩、整除、多项式根与插值、有限计数与纤维容量、离散求和与递推六个本地模块。r4 新增同余与中国剩余定理（23 条定理）、有限凸组合与 Jensen 不等式（22 条定理）、Gram 矩阵与最小二乘（22 条定理），合计再补入 67 条定理，并复用已验证的 50 个旧模块编译产物。累计九个本地模块通过 host-authored 库规范 run 验收，`authoring.json` 保留全部真实 run、源码 commit、回执及编译摘要，源码副本位于 `authored/`。上游声明及 `Sources:` 文档继续保留，兼容修改和源码摘要见 `compatibility.json` 与补丁。版本、目录摘要、包摘要和各文件摘要共同固定所选内容；标准库题目不安装该 Mathlib 库。其他 Mathlib 库可通过路径和固定目录摘要配置，构建与运行必须使用同一目录，见 [版本化库目录](library-catalog.md)。

worker 镜像通过 `scripts/prepare-web-library.ts` 直接调用固定 Lean 编译该目录，陈述预检从 `/opt/theoremos-library/.lake/build/lib/lean` 读取相同模块；证明运行仍独立重检所选冻结文件。没有个人历史 catalog 的新账号也能检索已安装库；host 在模型调用前尝试完整的 12 条应用候选，每个分支须关闭全部目标，实际调用只在通过 Lean 检查的证明包含库声明引用后记录。快照来源与兼容范围见 `resources/theorem-os-library/README.md`，不随公开网站导出。

知识检索以所选任务的精确类型或目标和当前记录的环境摘要作对照，显示历史环境一致、不同或缺失；当前环境缺失时明确显示无法比较。检索保留其他问题中的可复用材料，不自动限定来源问题。切换任务、任务版本或环境会清除旧详情并重新检索，引用附上关联任务及版本。环境或目标文本一致仍属于历史证据，路线发现的适用范围没有完整记录时继续标为未确认。

研究配置内除浏览器本地方案库外，还提供服务端方案库和实际模块注册表。服务端方案可保存、更新、另存、载入和确认删除，最多保留 12 项；删除释放方案容量并保留当前模块草稿。其他页面修改后的方案须刷新核对再删除；删除响应丢失时先读取服务器结果，不自动重发。注册表列出实现 ID、版本、输入输出合同与适用范围；仅可选择已安装实现，不接受浏览器上传执行代码。M3 的调度实现与 M4 的上下文实现可以选择，自定义文本仍属于策略建议。运行创建时固定实际组件与 method digest，保存方案或编辑草稿只影响后续新运行。

直接启动默认持久目录为 `out/web-data`；Compose 使用 `research-data` 命名卷保存到 `/var/lib/theorem-os`。同一浏览器会话可在服务重启后继续查看记录、知识和服务端方案。服务重启不会自动恢复求解：未完成运行明确标为中断；正常停止会取消运行，并在删除临时容器前尝试采集证据。默认持久会话闲置 30 天到期，可通过 `THEOREMOS_WEB_SESSION_TTL_SECONDS` 调整。未启用登录时，Cookie 丢失或会话到期后记录随会话删除，没有找回入口；启用登录后记录归属账号，见下节。删除运行会删除其归档及原始运行记录，已导入的知识 catalog 保留为独立版本。

### 账号登录

已通过邮箱验证码登录的账号，可在账号窗口设置至少 12 位、最多 256 字节的密码，随后在登录页选择密码登录。邮箱仍是账号名，内测白名单继续生效。密码只以随机盐的 scrypt 摘要保存在数据目录的 passwords 子目录，不通过接口返回。每个邮箱每小时最多尝试 5 次、每个 IP 每小时最多 20 次；密码登录也会更换会话 ID 和 CSRF token。修改密码需当前密码；忘记时用邮箱验证码重新登录，可在 10 分钟内直接重设。修改密码会退出其他设备，删除账号时密码摘要一并删除。

`THEOREMOS_WEB_PUBLIC_URL` 不是本机回环地址时，服务默认要求邮箱验证码登录，未配置发信会拒绝启动；本机预览默认匿名。显式设置 `THEOREMOS_WEB_AUTH=none` 可关闭登录，`email` 可在本机开启。

- 未登录（没有会话，或会话还没有账号）访问 `/` 或 `/index.html` 时，服务端直接 302 到 `login.html`，不加载工作台脚本、样式和数学排版资源；首次访问因此只下载登录页本身的资源。地址里的运行或对话（`?run=<id>`、`?chat=<id>`）带到登录页，登录后回到它；打开着的页面发现会话已结束时也这样跳转。
- 登录页 `login.html` 先要求输入图形验证码（5 位数字，服务端生成 SVG，5 分钟有效，每张只能用一次），再向邮箱发送 6 位验证码。验证码 10 分钟有效，输错 5 次作废；同一邮箱 60 秒内不重发、每小时最多 5 封，同一 IP 每 10 分钟最多请求 10 次。
- `THEOREMOS_WEB_SIGNUP=allowlist`（默认）时只有内测白名单中的邮箱能收到验证码；`open` 时任何邮箱都能注册登录，白名单只用于内测和优先名单。白名单来自 `THEOREMOS_WEB_ALLOWLIST`（逗号分隔）和 `allowlist.txt`（每行一个邮箱，`#` 后为注释）。`allowlist.txt` 默认放在数据目录根下，Compose 中为 `research-data` 卷内的 `/var/lib/theorem-os/allowlist.txt`，每次请求重新读取，改动无需重启。移出白名单的邮箱在下一次请求时退出登录，记录保留。
- 登录成功后更换会话 ID 和 CSRF token。运行记录、归档、知识目录和服务端方案归属账号：同一账号的多个浏览器看到同一份记录，退出登录或会话到期不删除记录。账号菜单可以退出登录，或输入邮箱确认后删除账号；删除会取消运行中的任务并立即删除全部记录。
- 启用登录时，已登录 Cookie 只在登录或重新登录时写入，浏览器保留期限为 365 天；普通 API 和会话核对不重写身份 Cookie，避免旧标签页的迟到响应覆盖新登录。实际登录有效期仍按服务端 `THEOREMOS_WEB_SESSION_TTL_SECONDS` 计算闲置时间，每次有效请求续期；闲置到期或会话因退出、其他设备改密码、撤销资格而结束后，保留的 Cookie 不能继续访问。登录前新建的匿名 Cookie 仍按配置的会话期限保存。关闭登录时保留匿名会话 Cookie 随有效请求续期的行为。
- 运行自行结束（完成或出错）时，服务给所有者的登录邮箱发一封结束邮件：题目标题、结论（通过验收、未通过、出错）、用时和回到该运行的链接 `/?run=<id>`，不含源码、证明、报告或 API Key。所有者停止的运行和服务重启中断的运行不发。账号对话框的「研究结束时发邮件」默认打开，关闭后账号文件记 `completionEmail: false`（`PATCH /api/auth/account`）；移出白名单的账号也不再收到。链接在未登录时由服务端直接 302 到 `login.html?run=<id>`，登录后回到 `/?run=<id>` 打开该运行。发信失败只在服务日志记一行运行 ID，不影响运行。内容由 `apps/web/completionMail.ts` 生成。
- 账号文件保存在数据目录的 `accounts/` 下，含账号 ID、邮箱、创建时间（即首次登录），以及首次提交运行 `firstRunAt` 和首次通过验收 `firstAcceptedAt` 两个时间，只在第一次发生时写入，删除账号时一起删除。验证码只以 HMAC 形式保存在内存中，服务重启后作废。
- 内测漏斗只输出汇总人数，不输出邮箱：`bun scripts/web-funnel.ts --data /var/lib/theorem-os [--applications N] [--github] [--json]`。步骤为申请 → 白名单 → 首次登录 → 首次提交 → 首次通过验收，每步给出占上一步的比例，以及登录到首次提交、首次提交到首次通过的中位小时数。`--applications` 填邮件申请数，`--github` 用 `gh` 读取公开仓库 `early-access` 标签的 Issue 数，两者相加；都不给时从白名单开始。移出白名单但登录过的账号仍计入白名单。这两个时间字段上线前创建的账号只计入首次登录。
- 管理员由 `THEOREMOS_WEB_ADMINS`（逗号分隔，需要 `THEOREMOS_WEB_AUTH=email`）指定，不必另写进白名单。管理员的账号菜单和命令面板多一项「管理」：查看上面的漏斗人数、白名单（标出来自管理员配置、部署配置还是白名单文件，以及是否登录过）和账号列表（邮箱、首次登录、首次提交、首次通过验收的时间）。白名单文件里的邮箱可以在线加入和移除：加入时追加一行，移除时删掉该邮箱所在的行，注释保留，写入经临时文件改名完成；移除后该账号的会话立即结束，账号和记录保留。环境变量里的邮箱只能改部署配置。管理接口 `/api/admin/*` 对其他账号一律返回 403，也不返回账号 ID、运行或题目内容，管理员看不到其他账号的记录。
- `THEOREMOS_WEB_ADMIN_KEYS` 可以让服务器替管理员保存服务商 Key，值是 JSON 对象 `{"<服务商 ID>": "<Key>"}`，只认已配置的服务商，需要 `THEOREMOS_WEB_ADMINS`。管理员提交时 Key 留空，服务器就用这里的 Key；手填的 Key 优先。会话只告诉管理员哪些服务商有保存的 Key（`account.serverKeys`），Key 本身不会发给浏览器，也和手填的 Key 一样不写入运行记录、出现在输出里时替换为 `[REDACTED]`。其他账号留空仍返回 400。启动时格式错误的报错只写服务商 ID，不写 Key。改 Key 后要重建容器。
- 设了 `THEOREMOS_WEB_KEY_SECRET`（64 位十六进制，需要 `THEOREMOS_WEB_AUTH=email`，生成：`openssl rand -hex 32`）后，每个账号可以把自己的 Key 保存到服务器（`apps/web/keyVault.ts`）。Lean 模型连接里的「保存到我的账号」默认不勾选，新填 Key 仅临时使用；只有主动勾选后提交才带 `saveKey: true`，自然语言设置则通过独立保存按钮主动保存或替换，运行创建成功后服务器用 AES-256-GCM 加密，存到数据目录 `keys/<sha256(账号 ID)>.json`（0600），每份密文绑定账号 ID、服务商 ID 和服务商地址，拷给别的账号、换了地址或换了密钥都解不开，按没有保存处理。密钥只在服务环境里，不进数据目录。会话的 `account.keyVault` 表示可以保存，`account.savedKeys` 只给服务商 ID 和末四位；Key 留空时依次用本账号保存的 Key、管理员的服务器 Key，都没有返回 400；手填的 Key 优先，只有勾选时才替换保存的 Key。`DELETE /api/auth/keys/<服务商 ID>` 删除一个，删除账号时一起删除。其他账号看不到、也用不到。开启后不再显示「在此标签页记住」。换密钥会让已保存的 Key 全部失效，用户需要重新填写。
- 本机调试可设 `THEOREMOS_WEB_SMTP_URL=log:`，验证码打印到服务日志，不发邮件；该值只允许用于回环地址。
- 开放注册时，第一次登录的验证码请求必须带 `terms: true`，否则返回 400「请先阅读并同意使用条款与隐私说明。」，验证码同时作废，账号不建立。账号文件记下同意的版本 `termsVersion` 和时间 `termsAt`，版本来自 `THEOREMOS_WEB_TERMS_VERSION`（默认 `2026-11-07`，与 `terms.html`、`privacy.html` 顶部的版本行一致）。改条款时同时改这两个页面的版本行并更新该变量；已注册账号再次登录不会重复询问。
- 每个账号按种类计用量，窗口到期后重新计数：研究 `THEOREMOS_WEB_QUOTA_RUNS`（默认 24 小时 30 次）、形式化 `THEOREMOS_WEB_QUOTA_FORMALIZATIONS`（8 次）、证明讲解 `THEOREMOS_WEB_QUOTA_EXPLANATIONS`（4 份），窗口长度 `THEOREMOS_WEB_QUOTA_WINDOW_HOURS`（1 小时至 30 天）。额度在创建前扣除，创建失败（参数不对、队列已满）时退回；重放的提交和已开始的运行不重复计数。超限返回 429 和一句说明，已开始的运行不受影响。记录写在数据目录 `usage/<sha256(账号 ID)>.json`，只有计数，删除账号时一起删除。管理员不受额度限制，会话里也没有这份数据。账号对话框显示本窗口剩余次数。
- 用量额度只记账，不接支付；把某个种类设为 0 等于关闭该功能。要临时放开某个账号，把邮箱加入 `THEOREMOS_WEB_ADMINS`。

```bash
THEOREMOS_WEB_PUBLIC_URL=https://workbench.example.org \
THEOREMOS_WEB_SMTP_URL='smtps://user:password@smtp.example.org:465' \
THEOREMOS_WEB_MAIL_FROM='TheoremOS <login@example.org>' \
THEOREMOS_WEB_ALLOWLIST='alice@example.org' \
THEOREMOS_WEB_ADMINS='admin@example.org' \
docker compose -f apps/web/compose.yml up -d web
```

SMTP 密码只放在环境变量或 `.env` 中，不要写进仓库。服务在反向代理或 Cloudflare Tunnel 后面时，所有请求都来自代理，按 IP 的限流会把访客算成同一个人；设 `THEOREMOS_WEB_CLIENT_IP_HEADER=cf-connecting-ip`（或代理写入的其他请求头）改按访客地址计数。只在端口仅对代理开放时设置，否则直连的客户端可以自己填这个请求头。

### 协作 HTTP 接口

这些接口沿用当前会话归属、同源和 CSRF 检查；路径中的运行 ID 为 Web ID，solver ID 单独包含在观测中。浏览器不能指定容器文件路径或 shell 命令。

| 接口 | 用途 |
| --- | --- |
| `GET /api/runs/:id/observation` | 当前运行观测、完整计划、任务、Agent、数学前沿及历史证据 |
| `GET /api/runs/:id/events?after=N` | 按序号分页读取已保存事件，返回保留范围 |
| `GET /api/runs/:id/tasks/:taskId/source?version=V` | 指定任务版本的 owned-file 源码与身份 |
| `GET /api/runs/:id/checks/:receiptId` | 已记录的检查回执 |
| `POST /api/runs/:id/guidance` | 提交带幂等 ID 和观测引用的指导 |
| `GET /api/runs/:id/guidance/:guidanceId` | 指导投递状态 |
| `POST /api/runs/:id/edits/preview`、`POST /api/runs/:id/edits` | 预览或提交完整版本化计划 |
| `GET /api/runs/:id/commands/:commandId` | 查询原命令回执、应用或投递状态 |

直接下载和新保存的完整归档使用 `theorem-os.web-archive.v2`。任务、依赖和原生团队证明的源码使用 `{"sha256":"…"}` 引用，按摘要在同一文件的 `sourceBlobs` 对象中查找原文。历史观测、最近观测、命令回执附带的观测和顶层源码索引共用这份原文表。早期 v2 归档的原生团队源码为内联文本。摘要继续记录覆盖范围和证据数量，`summary.digest` 绑定实际导出的内容。旧 v1 归档按保存时的格式和摘要下载。工作台可以从两版归档和 `theorem-os.web-export.v1` 运行快照导入任务草稿，并保留明确选择的「不使用历史知识」。

### 配置研究模块

打开「研究配置 → 模块方案」，或点击草稿模块图中的配置图标，可选择 M3 搜索策略与 M4 上下文范围，并新增自定义策略。每项策略包含名称、所属模块、规则、启用开关及「补充默认建议 / 替换默认建议」。支持 M1 证明构造、M3 搜索决策、M4 上下文选择和 M5 协作与复用；M2 检查及 S3 最终验收保持固定。

「模块方案 → 方案库」可命名保存、更新、另存、载入和删除模块组合，同一浏览器最多保留 12 项，每项名称最多 40 个字符。方案库独立于任务草稿，刷新或新建研究后仍保留；仅保存模块配置，不保存任务、Lean 源码、API Key、模型或执行预算。未完成的模块规则也可保存为方案，载入后仍需通过提交校验。

载入方案只替换当前模块配置，同步草稿自动保存与模块图。载入后可撤销，恢复载入前的模块配置并保留任务、源码及预算等其他编辑；继续编辑模块、替换草稿、重置、刷新或提交研究后清除该撤销记录。删除已保存方案不修改当前配置，支持恢复最近删除的一项；恢复时若已满 12 项或名称冲突，会保留原库并提示原因。更新或删除其他标签页已经修改的方案时，需要重新选择，避免覆盖较新的内容。

方案库使用 `localStorage`，写入通过浏览器 Web Locks 协调多标签页操作，因此需要支持 Web Locks 的浏览器，并以 HTTPS 或 localhost（包括 `127.0.0.1`）访问。缺少支持、存储被禁用或容量不足时会显示失败，损坏的库不会被空库覆盖；研究工作台的其他功能仍可使用。方案保存在当前浏览器，暂不跨设备同步。

新增策略默认停用。点击策略右上角的复制按钮，可保留所属模块、策略方式和规则，创建独立副本；副本自动命名并默认停用，可改名、调整规则后再启用。最多保存 8 项，名称最多 40 个字符，单项规则最多 4,000 UTF-8 字节，规则合计最多 16,000 字节；同一模块最多启用一项替换策略，可同时启用多项补充策略。替换仅影响该模块的可配置建议，原题约束、必需数学上下文、角色协议、Lean 检查与独立验收仍会执行。自定义规则作为研究上下文交给模型，不支持上传可执行插件。M5 规则仅在多 Agent、协同模式且实际进入协作上下文时参与；M3 的任务调度预设也仅在协作任务中发挥调度作用。「精简上下文」移除可选材料，保留必需上下文。

策略可单项或全部展开、收起，收起时保留名称、所属模块、策略方式及启用开关。通过上下箭头调整列表位置；同一模块的规则按列表顺序加入上下文，跨模块排序不改变研究模块的执行结构。排序随方案保存和复用，校验时会自动展开并定位有问题的策略。

删除策略后，可通过模块方案底部的撤销图标恢复最近删除的一项，保留规则、原位置、启用及折叠状态，不覆盖其他策略的新编辑。达到 8 项上限时暂不能恢复。撤销记录仅在当前页面内保留，关闭配置后仍可使用；重置、导入、复用或恢复草稿、刷新及实际提交任务时清除。恢复的策略继续接受替换冲突和规则大小校验。

草稿模块图中，点击自定义策略会展开对应规则并定位到详情；详情中的编辑按钮可直接打开该项配置，关闭后返回对应策略。更换所属模块后会定位到新模块，删除后回到模块节点。M1、M3、M4、M5 详情中的新增按钮会创建归属于当前模块的停用策略；达到 8 项上限后禁用新增。已有运行中的模块方案只供查看，不提供编辑或新增入口。

草稿模块图的策略列表可直接启停规则，开关与研究配置、草稿保存同步。普通启停保留当前查看的模块、焦点和阅读位置；启用缺少规则或存在替换冲突的策略时，打开配置并定位待修正字段。已有运行隐藏开关，提交期间禁用编辑。

手机上从工作区打开研究配置时，关闭配置会返回原工作区；即使未修改配置，也会保留所选模块和策略的阅读状态。提交时回到对话；研究任务校验失败时定位到输入框，配置的关闭事件不会覆盖此次跳转。

模块方案随草稿自动保存，并随任务导入、导出、恢复与「基于此题新建研究」复用。提交时固定本次方案，后续草稿修改不影响已有运行。模块图显示停用、不适用、待应用和已应用次数；次数来自规则实际加入编译上下文的事件，不代表模型调用或证明成功，活动日志轮转后仍可查看累计记录。

更新已有 Docker 部署时，需要重新构建 worker 和 web 镜像，使两端使用同一版模块配置协议。

```bash
# 停止服务；未完成任务会被取消并清理容器
docker compose -f apps/web/compose.yml down
```

默认仅监听本机 8787 端口。请使用 `127.0.0.1` 访问；服务会校验 Host 与公开地址一致。GitHub Pages 只托管静态官网，无法运行此后端。

## 配置兼容 Responses API 的服务

服务商由部署者配置，网页访客从列表选择。地址使用 HTTPS；宿主机网关可使用 `http://host.docker.internal:端口/v1`。地址不能包含凭据、查询串或片段。工作台使用 Codex 的自定义模型服务配置 `wire_api = "responses"`、`env_key` 与 Bearer API Key；Sub2API 需启用 Responses API 兼容端点，仅兼容 Chat Completions 的服务暂不支持。

启动前在 shell 设置以下环境变量，再运行 Compose：

```bash
export THEOREMOS_WEB_PROVIDERS='[{"id":"sub2api","name":"Sub2API · DeepSeek","baseUrl":"http://host.docker.internal:8080/v1"},{"id":"openai","name":"OpenAI","baseUrl":"https://api.openai.com/v1"}]'
docker compose -f apps/web/compose.yml up -d web
```

上例与默认服务商列表一致；网关使用其他端口或 HTTPS 域名时，修改第一个地址。这里仅配置服务地址；用户的 API Key 在网页中逐次输入。

轨迹里的「问为什么」由网页服务自己调用服务商的 `/responses`（流式、`store: false`、`reasoning.effort: low`），不经过 worker。Compose 为 web 服务加了 `host.docker.internal:host-gateway`，宿主机网关地址在 web 容器里同样可达；直接用 Bun 启动时，`host.docker.internal` 需要能在本机解析。

## 功能范围与数据

- 提供 Mathlib 和 Lean 标准库两种固定环境。新网页任务默认 Mathlib，可使用 `import Mathlib` 和对应版本提供的 tactic；标准库环境不提供 Mathlib。单份源码最多 32 KiB，至少包含一个命名 theorem / lemma；保留原题声明，模型修改证明。暂不支持上传仓库或自定义 Lake 依赖。
- 提交前检查原题：源码或环境停止变化约 1 秒后，服务在一次性容器（无网络、只读镜像、2 CPU、标准库 30 秒 / Mathlib 90 秒）里用固定 Lean 单独编译 `Submission.lean`，不启动模型、不创建工作区。先做与运行时相同的结构检查（控制字符、声明数量、同名声明、缺少 theorem / lemma、无法识别的定理声明），不通过时不启动 Lean。输入框上方显示状态，研究配置的源码下方列出错误与警告，点击即在编辑器中选中对应范围（行从 1 计、列按 Unicode 字符计，与 Lean 一致）。当前文本有 Lean 错误时，提交会停在第一个错误处；用户可选择“忽略检查结果，仍然提交”，仅对这份文本有效。结构检查不通过无法忽略，因为运行时同样会拒绝。超时、服务繁忙或检查不可用时不阻止提交。服务端每个会话同时只保留一个检查（新的取代旧的），全局同时 2 个、排队 6 个，每会话每分钟最多 20 次编译；相同环境与源码的已完成结果缓存 200 条。没有 Docker 检查能力的部署不提供此功能（`session.precheck` 缺省）。
- 结果可读：报告页的“证明结构”列出原题目标（阐释后的类型、依赖的公理，Lean 三个标准公理之外的公理会被标出）和求解过程新增的辅助声明，并按独立验收记录的引用关系标出每个目标用到哪些辅助声明、每个辅助声明被谁用到（引用含间接依赖）；没有引用记录的旧运行只列声明，不从文本猜测用法。结构由服务端解析候选源码得出，因此也适用于未通过验收的候选。同一节提供“下载本地复核包”和逐步说明：`lake build Submission` 复现内核检查，`lake env lean Check.lean` 核对公理，比较 `Original.lean` 与 `Submission.lean` 确认陈述未改。未通过的运行在“卡在哪里”中列出仍未闭合的原题目标所依赖的前沿子目标（其余未完成的证明任务排在后面，最多 8 个）：Lean 类型、状态、尝试次数、最近一次检查的失败类别、仍开放的阻碍与最近反馈，并可一键在研究协作中打开该任务。
- 协作页分两层：首次打开是“简洁”层，只显示进展计数、“现在在做什么”（工作中的 Agent 与其任务、研究等待原因、结束后去报告的入口）和指导；依赖图、任务检查器、审阅、数学变化、Agent 分工、交付、记录与知识目录在“完整”层。选择按浏览器记在 `theorem-os.web-collaboration-detail.v1`；从简洁层或报告页打开任何任务会切到完整层并记住。浏览器测试默认以完整层启动（`web-scenario` 的 `collaborationDetail`）。
- 未开启账号保存 Key（见 `THEOREMOS_WEB_KEY_SECRET`）时，API Key 默认每次提交后清空。设置里勾选“在此标签页记住”后，Key 存在 sessionStorage 的 `theorem-os.web-api-key.v1`（关闭标签页即清除，其他标签页拿不到），只对填写时的服务商与地址生效，从不写入 localStorage 或草稿；取消勾选、点“清除已记住的 Key”、因认证失败去更换 Key、登出或切换账户时立即清除。
- 静态文件由 `apps/web/staticFiles.ts` 发送：HTML、JS、CSS 按浏览器支持用 Brotli 或 gzip 压缩（内存缓存，文件重建后下次请求生效），全部带 ETag 和 `Cache-Control: no-cache`，重复访问只需 304 重新验证；API 仍是 `no-store`。加载预算见 `test:web-load`。
- 顶栏右侧依次是经典题库、搜索（打开命令面板，也可按 Ctrl / ⌘ K）、研究配置、术语说明、语言、连接状态和账号。560 像素以下省去术语说明（命令面板、欢迎页和各处 `?` 仍可打开），420 像素以下只留 Logo 图标、不显示文字；顶栏放不下时只截短账号邮箱，其他按钮保持原尺寸，所有按钮至少 24 像素见方。
- Windows 高对比度（`forced-colors: active`）下浏览器会换掉背景、边框颜色和阴影，只靠这些表示的状态会消失。当前、选中、按下和勾选的控件改用系统 Highlight 色的内描边，有焦点时保留焦点环；命令面板的当前项和模块开关画成系统色；用户消息、原题框和发送按钮画成线框；输入框获得焦点时外加 Highlight 描边。这种模式下浏览器把所有文本高亮都画成选中色，因此 Lean 源码不做语法着色，只保留查找匹配；退出该模式后着色恢复。
- 外观：默认跟随系统浅色/深色；账号对话框的“外观”或命令面板可固定为浅色或深色，选择存在 localStorage `theorem-os.web-theme.v1`，同浏览器其他标签页同步。三个页面在 `<head>` 里同步加载 `theme.js`，首帧前就在 `<html data-theme>` 上定好主题；样式只读这个属性，深色只替换 `:root` 里的颜色、阴影与代码配色变量。阴影与遮罩统一用 `--shade`，两种主题下都保持暗色。

- 通过独立验收的运行可由所有者创建分享链接 `share.html#<token>`。创建前列出公开与不公开的内容；链接打开一份创建时的只读快照，包含研究任务、原始题目、验收证明、验收结论（不含诊断原文）、Lean 工具链 / Mathlib 版本 / 源码摘要、模型名称、Agent 数量、轮次、耗时和 Token 用量，不包含 API Key、服务商、运行 ID、活动日志、协作记录或账号邮箱。查看无需登录，也不会创建会话；页面与接口带 `noindex`，token 放在 `#` 后不进入请求日志。停止分享、删除运行、删除账号或匿名会话到期都会立即使链接失效；重新分享生成新链接。快照保存在运行目录的 `share.json`，`shares/` 下只按 token 摘要记录运行位置。
- 证明讲解：通过独立验收的运行，在结果页验收证明和源码工具栏中直接显示“Lean → 自然语言”，在新标签页打开 `explain.html?run=<id>`，可在讲解页选择目标定理；入口不依赖报告视图或证明结构加载。报告页“证明结构”里仍保留每个原题目标的“证明讲解”链接（`explain.html?run=<id>&target=<name>`）。示例也显示查看入口，页面说明示例只读、不提供生成按钮，返回工作台时回到示例。页面左半是完整的 Lean 证明（行号、着色），右半是自然语言证明。开头是主定理与证明思路，可以直接跳到主定理的证明。每个声明一节，每一步标出它引用的 Lean 行和用到的引理。点一步会标亮并滚到对应的 Lean 行，点一行 Lean 会标亮并滚到解释它的那一步，点引理名跳到该声明的一节，这时右侧标题栏出现“返回阅读位置”，它和浏览器的后退（手机的返回手势）一样回到跳转前的滚动位置、选中的一步和所在的一侧，焦点回到那个引理名；连续跳几次就一次退回一处，地址不变，离线报告里后退也不会离开文件。定理的“陈述”对应它的签名（从声明开头到第一个括号外的 `:=` 或 `where`），点陈述标亮签名，点签名行回到陈述；行号右侧的窄栏在每一步引用的第一行写步骤号，签名行画一道竖线，没有任何一步引用的实质证明行（不算只有 `by`、`·`、括号的行）画一个空心圈，点这样的行会打开所在声明并说明它没有单独的讲解步骤，栏上方有图例。重复出现的同一段策略按步骤顺序对应到后面的那一处。“用到”里的名字分三种：写在这一步引用的 Lean 里、写在这个声明的其他行里、源码里没有直接写出（经记号或自动化用到，显示为虚线框的纯文本）；库里的名字指着或点击时在 Lean 中标出它出现的位置（CSS Custom Highlight API，浏览器不支持时只标亮所在行）。审核模型对陈述和每一步写的说明折叠在“审核说明”里，空的不显示；证据带 Lean 目标时，每一步折叠显示“Lean 目标”：它引用的最外层策略中第一个之前、最后一个之后的目标（Lean 原文，不翻译，最多 4 个，多出的写明个数），没有这一信息的旧讲解不显示；开头的“讲解来源与审阅”可展开查看逐步讲到的证明行数和重复引用片段。页面上的对应关系不保存：每次打开时服务端重新校验证据再算出来，校验不通过时页面只说明讲解没有通过完整性检查；“同步滚动”打开时（默认）两边跟随读者正在滚动的一侧。宽度不超过 900 像素时一次只显示一侧、也不同步滚动，过长的 Lean 行就地折行，折下的部分比这一行本身的缩进再缩进 4 个字符，不必左右滑动。Lean 名字只在 `.` 或 `_` 之后折行；宽度不小于 360 像素的手机上，目标名和两侧切换按钮在同一行；高度不超过 480 像素时（如横握手机），窗格上方的几条栏变矮，窗格仍占约三分之二的高度。`$…$` 公式由页面自带的小型 TeX 读取器画成普通元素，读不懂的公式按原文显示；行内公式过长时只在括号外的关系符、运算符或逗号之后折行（前导负号和 `:=` 不算），其余部分不拆开。新运行默认自动生成全部原题目标的讲解，使用解题时的 Key、模型和推理强度（低→低，中/高→高，很高/最高→最高）；Key 仅在执行输入中驻留，不随记录保存。讲解生成与证明预算分别计算，默认不限制讲解时间、Token 或审核轮数。API 可通过 `autoExplain: false` 关闭自动生成，并用 `explanationLanguage: "zh" | "en"` 固定语言。历史记录、失败后重试或另一种语言可在讲解页点“生成讲解”，对话框给出按声明数估算的时间与 Token（参考：14 个声明约 4.5 小时、1075 万 Token）；手动生成的 Key 依次取账号保存的 Key、服务器 Key，都没有时在对话框里填写。目前只支持 sub2api 网关上 `deepseek-flash` 的运行；示例运行、未验收的运行、其他服务商或模型会说明原因而不提供按钮。生成在服务器上一次只跑一个（自动生成按一次运行占一个接收名额，各目标依次生成；手动生成按每份讲解占一个名额，全局最多 4 个、每账号最多 2 个名额），每个在独立容器里进行（2 CPU，Mathlib 12 GB / 标准库 4 GB 内存，`/var/tmp` 卷存放固定环境与角色编译，Mathlib 约需 20–35 GB 磁盘），页面每 5 秒刷新进度，可确认后停止；服务重启时未完成的讲解记为中断。同一运行的每个目标和语言（中文 / 英文）各有一份，存放在运行目录的 `explanations/<摘要>/`（`record.json` 与通过审核的 `evidence.json`），服务端在记为通过前、每次打开讲解和每次下载 Markdown 时都重新校验证据与这次运行的证明一致，`record.json` 不存页面文档；可下载 Markdown，可确认后删除，删除运行时一并删除。讲解由模型写成并由模型审核，页面顶部写明 Lean 只检查了证明本身。工作台生成的新讲解使用短语对齐（`lean-phrase-alignment-v2`）：陈述和每一步里划虚线的短语各对应一段 Lean（陈述的短语落在签名里，步骤的短语落在这一步引用的 Lean 里），点击或聚焦后按 Enter / 空格在左边精确标出这段 Lean，指针移入时预览；短语落在公式、代码或加粗里时整段一起标，公式不会被拆开。审核模型核对每一对短语，并把每一步的讲解和它的 Lean 目标逐个对照，判断一致的步骤在“Lean 目标”标题旁写“N 个审核模型对照过”，判断不一致时讲解不通过。只引用块状策略开头的一步（如 `induction n with`、`have h : P := by`），“之后”列出这个开头留给块内策略的目标，再接整个块之后的目标，而不是整个块结束后的状态。用 `lean-phrase-alignment-v1` 生成的讲解在这类步骤上当时审核的是整个块的目标，页面改显示新的目标，这些步骤不再写“对照过”。之前生成的讲解没有短语和这条标记。从形式化结果开始的讲解会在正文前多一节“原题”，目前只能在命令行生成，工作台的讲解没有这一节。生成流程见 [证明讲解](informalization.md)。
- 离线报告页：`bun run math informalize --phase report` 和 `bun run math formalize --phase report` 各把一份通过审核的讲解或形式化写成单个 HTML 文件（只读，脚本、样式、字体都在文件里，CSP 禁止任何外部请求），不需要服务器和登录，直接用浏览器打开。讲解报告和工作台的讲解页相同，只是没有生成、删除和切换语言的按钮；形式化对照页左边是 Lean 陈述，右边是原题，原题里划线的片段对应 Lean 陈述的一段（点片段、点 Lean 行或点对照项都会互相标出），下面依次是逐项对照、盲回译、形式化计划和原文覆盖。讲解页（含工作台上的）和对照页打印时排成一份文档：先是讲解或原题与审核，Lean 从新的一页开始并整段折行，按钮不打印，深色主题也用浅色打印；折叠的内容按读者当时展开或收起的样子打印。`bun run build:web` 把讲解页脚本放在 `out/web/`、对照页放在 `out/web-report/`；服务端不提供 `out/web-report/`，这两页只通过命令行生成。命令和参数见 [证明讲解](informalization.md) 与 [形式化](formalization.md)。
- 已完成、已取消或发生错误的历史记录可在确认后单条删除，删除前可下载包含原始题目与诊断的运行档案，即使任务尚未生成结果。排队或运行中的任务不能删除；删除不会自动取消任务。删除后释放会话的历史容量，不影响其他任务。删除请求的响应丢失时只刷新历史核对，不自动重发。
- 网络中断或请求超过 15 秒时显示连接状态并禁用提交，已有表单仍可编辑；网络恢复、返回页面或手动重连时自动刷新会话和历史。创建任务与取消请求均不自动重发；提交响应丢失时提示结果未确认，并通过历史列表核对，避免重复创建任务。恢复连接不重置未提交的源码、任务或模型配置。
- 取消请求等待期间，对话停止按钮、详情操作和运行状态栏同步显示正在取消，重复操作不会再次发送请求。若轮询已确认该任务取消或结束，迟到的取消响应错误不会再将结果标为未知，也不会因此断线重连；无法确认时仍保留核对提示，不自动重发取消请求。
- 可配置 1–4 个 Agent、任务协作 / 独立并行、1–20 轮和 30–900 秒解题预算。Mathlib 冷准备最长 600 秒，标准库准备和最终验收各有独立时限，均不计入解题预算；轮次和时间不等于 API 费用上限，服务商按自己的计费规则收费。
- 模型结束和网页显示“运行结束”都不代表证明成立。只有 `evaluated_passed` 才显示“验收通过”；这是本地独立 Lean 验收，不是 Lean-Eval 官方成绩。
- 浏览器不把 Key 写入 localStorage / sessionStorage；提交成功后清空输入框。保存到账号的 Key 只以密文存在服务器上，浏览器只拿到末四位。Key 经同源后端内存、Docker stdin 与 Codex 子进程环境传递，不写入 Docker 参数、容器环境配置、Codex 配置文件、任务档案或服务日志。每个任务使用新的 Codex profile，不读取部署者的认证文件；工具 shell 环境排除该 Key。
- 默认将运行记录、完整事件、观测、源码、回执、知识和服务端方案保存到私有持久目录。每个会话最多保留 40 条运行记录，可删除已结束的记录以释放容量；这是保存记录的容量，与账号在配额周期内可发起的次数、运行队列和并发限制分别计算。有效 API 请求延长服务端会话的闲置有效期；匿名运行同时续期 Cookie，启用登录时仅在登录时写入身份 Cookie。同一会话在有效期内可跨服务重启读取历史，启用登录后也可跨设备查看账号历史；服务不会自动恢复执行。测试中不设置持久目录的嵌入式服务仍仅使用内存。

## 部署到服务器

在 Linux 服务器按上述命令构建或拉取 GHCR 镜像并运行，再用 Nginx / Caddy 将 HTTPS 域名反向代理至 `127.0.0.1:8787`。设置 `THEOREMOS_WEB_PUBLIC_URL=https://research.example.com`，保留原始 Host 请求头。服务设置 Secure / HttpOnly / SameSite Cookie，并检查请求来源与 CSRF token。不要在反向代理中记录请求体；其中包含访客 Key。

Web 容器是 Docker supervisor，挂载 Docker socket，有权限创建和删除运行容器。请将它部署在用于此产品的受控宿主机上。Worker 以 UID 10001 和只读根文件系统运行，不挂载 Docker socket 或宿主目录。每次证明运行有一个挂载到 `/var/theoremos-proof` 的独立磁盘卷。Worker 在这里覆盖保存脱敏后的最新候选、观测和终局回执。Docker 输出连接中断时，supervisor 等待容器结束，从卷中读回回执，再清理容器和磁盘卷。求证工作区使用 `/work` 的临时文件系统，模型服务密钥经标准输入传入。标准库运行使用 `/var/tmp` 的临时文件系统存放 Lean 检查缓存。Mathlib 运行映射 `/dev/fuse:rw`，并使用挂载到 `/var/tmp` 的匿名磁盘卷准备验证环境。

为嵌套的非特权 Bubblewrap 验证器，worker 放开容器 seccomp / AppArmor profile，并使用 `systempaths=unconfined` 允许在独立 PID 命名空间内挂载新的 procfs。Mathlib 入口的外层 Bubblewrap 在新 user namespace 内仅授予 `SYS_ADMIN` 和 `SETFCAP`，用于构造冻结的依赖环境；Docker 容器仍保留 `--cap-drop=ALL`、`no-new-privileges` 和资源限制，不共享宿主机 PID 命名空间。`/tmp` 的 tmpfs 显式启用 `exec`，供验证器运行临时 Lean 启动脚本，并保留 `nosuid,nodev`。宿主机需要支持这一隔离方式；不支持时应修正宿主机配置，不能跳过 Lean 验证隔离。

公网默认启用邮箱登录；只有显式设置 `THEOREMOS_WEB_AUTH=none` 的自托管实例允许匿名提交。普通 API 每 IP 每分钟最多 600 次，新建会话另限每 IP 每十分钟 30 次；登录页匿名会话池满时回收最旧匿名会话，已登录会话不会被挤出。匿名本地工作台不采用淘汰，因为其会话拥有运行记录。反向代理应正确配置可信的 `THEOREMOS_WEB_CLIENT_IP_HEADER`，不能接受来自任意客户端的伪造头。

### 部署来源

在干净检出中运行 `THEOREMOS_SOURCE_COMMIT=$(git rev-parse HEAD) docker compose -f apps/web/compose.yml build worker web tex`，给三个镜像传入同一提交。三个镜像都带 `org.opencontainers.image.revision` 标签，Web 的 `/healthz` 和前端 `build-info.json` 也记录提交。部署后在同一检出目录运行 `scripts/web-deploy-record.sh <THEOREMOS_WEB_PUBLIC_URL> >> deploys.jsonl`（服务只接受该地址的 Host），一行记录提交、工作区是否干净、web、worker 和 tex 的镜像 ID 与标签、运行中的 Web 容器镜像，以及线上与镜像内 `app.js` 的 SHA-256。`clean` 检查受控变更和未跟踪文件（不含 Git 忽略文件）；false 时该提交不能代表部署内容。构建应核对忽略文件是否进入 Docker 上下文。记录只采样 `app.js`，不覆盖全部静态资源，也不验证实际运行的 worker 容器。回滚使用部署前打的镜像标签，回滚后同样记录一行。

### 有效容量

各队列互相独立，数字均为服务端硬限制：

| 队列 | 同时执行 | 等待+执行上限 | 每账号 |
| --- | --- | --- | --- |
| 原题形式化 | 1 | 8 | 最多 2 个等待或执行中的任务、保留 20 条 |
| 证明研究 | `THEOREMOS_WEB_CONCURRENCY`（默认 1，最多 8） | `THEOREMOS_WEB_QUEUE_LIMIT`（默认 8） | 保留上限见运行记录 |
| 提交前 Lean 检查 | 2 | 8（另排队 6） | 每页面 1 个、每账号每分钟 20 次 |
| 证明讲解 | 1 | 4 个接收名额 | 2 个接收名额 |

命令行 `run` 同样在验收后生成讲解；`import:math-results` 读取已审核产物，核对接受 commit 与全部源文件摘要后交给经典题库的通用阅读器，无需新增手写 `proofWalkthrough*.ts`。多文件讲解保留真实文件名和行号。

自动讲解按一次解题占一个接收名额，其全部目标逐项执行；每个实际开始生成的目标使用一份账号讲解额度，等待原题审核或被取消的未开始目标不扣额度。额度耗尽、队列已满或生成失败会保存原因，原证明验收结果保留；用户可稍后手动重试。服务重启将未完成讲解标为中断，不持久化 Key、不自动重跑付费任务。

形式化通过后自动入证明队列；证明队列已满时形式化记录标为 `formalization_research_queue_failed`，用户可显式继续已冻结陈述。重试校验冻结证据、原服务商地址和记录归属，并幂等返回同一 runId。形式化与证明各占自己的执行位，因此 A 的证明运行时 B 的形式化可以同时执行，B 的证明随后在证明队列排队。关联 ID：形式化记录 `id` 等于证明运行的 `formalizationId`，形式化记录的 `runId` 指回该运行，两者都只能由所属账号读取。模型网关自身的并发（例如每个 Key 的上限）不在这些数字内；提高 `THEOREMOS_WEB_CONCURRENCY` 前须确认网关和宿主机 CPU/内存能承担。对应回归见 `tests/webFormalizations.test.ts` 的双账号排队用例。

如果首页提示“运行镜像尚未就绪”，确认 worker 镜像已构建，Web 服务能访问 Docker daemon，且镜像标签一致。如果镜像就绪但 Lean 验收无法执行，先运行上述离线 Docker 验证，检查用户命名空间和 Bubblewrap 的宿主机支持。

### 创建请求与本地草稿隔离

浏览器的任务草稿、替换前恢复副本和待确认提交绑定当前账号（匿名模式绑定会话）。同账号刷新保留草稿；显式退出或删除账号会清除这些内容并停止离开页面时的回写，同时通知其他打开的标签页。登录身份变化时不恢复旧账号内容；无法确认归属的旧版本地草稿也不自动恢复。导入和导出的任务文件格式不变。

每个页面用独立的 `checkScope` 提交预检。同一账号的不同页面互不取消；同页面新编辑替换旧检查。账号每分钟限额和全局并发/排队上限仍共同生效，409 或检查失败会退出“检查中”，可以重新检查。

`POST /api/runs` 接受可选的 `requestId`，也兼容 `Idempotency-Key` 请求头；两者同时提供时必须一致。标识为 1–128 位字母、数字、下划线或连字符，作用域限于当前 owner。同标识、同题目和执行配置返回原运行，不重复排队；不同配置返回 409；已删除运行返回 410。模型 key 和是否保存 key 不属于执行身份，重试不会修改已启动运行的凭据或再次保存 key。未带标识的旧客户端仍是每次请求创建新运行。

浏览器在响应丢失后保留原请求标识，刷新后重试也复用它（浏览器存储不可用时仅当前页面保留）；修改题目/执行配置或选择“新建研究”会使用新标识。请求身份与初始运行在启动 worker 前一起保存；配置数据目录后可跨服务重启核对原运行。重启后的未完成运行仍标记为中断，不自动继续执行。部署保持单个 Web supervisor 写入同一数据目录，不支持多个服务进程共用目录并发创建。

`bun run test:web-review-regressions` 使用本地 HTTP、虚构账号及模拟 runner 验证账号切换、预检隔离、丢响应与刷新重试、队列和取消；它不调用模型或 Lean，不代替 Linux worker 的独立验收。
## 在线原题形式化

新建研究的「自然语言 / TeX → Lean」打开 `formalize.html`。原题全文提交到独立形式化任务；默认只运行生成和 Lean 编译，编译失败时把诊断交给生成模型修正，支持取消、刷新恢复查看及重新填写后显式重试。新记录冻结 `reviewMode: "direct"`，保存 v4 编译证据，明确 `semanticReview: "not-performed"`，不启动独立规划、回译或 Reviewer。独立形式化页编译通过后进入待确认状态，首页自然语言输入则自动衔接证明。编译通过不代表证明通过。

在独立形式化页核对原题与 Lean 后，可确认当前证据摘要，再带入研究草稿。旧审核记录保留其回译和审核结果。证明提交携带 `formalizationId`，服务端核对归属、确认状态、原题字节及环境，并将完整证据交给隔离证明 worker。worker 重建冻结原题，保留自然语言原题和证据摘要；复用与继续研究保留此来源。手动更改 Lean 或环境会将草稿转为普通 Lean 题目，不沿用原语义确认。

API 包含 `POST /api/providers/:id/check`（只读取模型列表，不调用模型）、`POST /api/formalizations/:id/research`（接续证明）以及 `GET/POST /api/formalizations`、`GET/DELETE /api/formalizations/:id`、`POST /api/formalizations/:id/cancel` 和 `POST /api/formalizations/:id/confirm`（含 `evidenceSha256`）。写操作沿用会话、归属与 CSRF 检查。凭据只驻留执行输入，服务端记录不包含 Key；账户已保存 Key 和管理员配置 Key 可直接使用。任务与证据保存于所有者目录，服务重启会把未完成任务标为中断，不自动重跑。

聊天与独立形式化页面在发送前保存按 owner 隔离的提交身份、原题和非密钥设置；响应丢失后，刷新并手动重试仍使用同一 `requestId`，不要求再次提供 Key，也不重复入队。相同身份和配置返回原记录，配置冲突返回 409，记录已删除返回 410。服务重启后返回中断状态，不自动恢复付费执行。独立页打开明确的记录或例题链接时优先展示链接目标，旧的待恢复草稿不会覆盖它。账号最多接收两项形式化任务，页面展示全局 FIFO 排队位置；运行、取消和后续证明仍按各自任务身份关联。

生成支持配置中的 Sub2API `deepseek-flash` 和 HTTPS Responses 服务（包括 OpenAI），原服务商、模型和预算随记录保存。形式化与后续证明的时间、Token 和证明轮次默认留空；留空或填 0 表示无限制，只有用户填写正数时才启用相应预算。单轮执行与宿主检查也不会为默认无限制的请求补入隐藏时间上限。显式填写的形式化时间最多 30 分钟、Token 最多 2,000,000；这些是有限预算输入的校验上界。默认只调用生成角色；每个账号最多两个等待或执行中的任务，全局单并发、最多 8 个等待或执行任务，每个账号最多保留 20 条记录。部署须同时重新构建 Web 静态产物和 worker 镜像，镜像 entrypoint 新增 `formalize` 分支；没有对应 runner 或服务商时页面说明不可用。原 CLI 与离线形式化报告保持独立。

Token 上限依据服务商返回的用量执行，进行中的请求可能超出；它与时间限制、每日次数额度都不是金额保证。费用由模型服务商收取。旧的零上限或 200,000 Token 证据仍可读取，新记录必须与实际提交的预算一致。页面区分形式化的编译结果与最终独立 Lean 证明验收；默认形式化没有独立语义审核，Lean 验收只保证冻结 Lean 陈述下的证明。

手动形式化工具中，自然语言原文或证明环境修改后，旧结果的确认和继续入口不可用，须重新生成并确认。选择历史记录时恢复其原文和环境，替换未保存输入前需确认。解题任务同时携带确认原文和对应 Lean 陈述，独立验收仍检查冻结的完整 Lean 原题。
